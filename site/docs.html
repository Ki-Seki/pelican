Pelican docs

Pelican runs next to Claude Code on your computer and gives it a web app made for a phone. This page covers setting it up and everything it does.

Install

You need Node 22.12 or newer, and Claude Code signed in on the same computer (run claude once and log in, or set an API key the way Claude Code reads it). Pelican brings its own copy of Claude Code through the Agent SDK, so a separate install is optional.

# try it first, with made-up sessions
npx pelican-cc --demo

# install it
npm install -g pelican-cc
pelican

Pelican prints a link, http://localhost:7860/?token=…. Open it: it signs this browser in, and your sessions are there already. pelican token prints it again. When Pelican listens beyond this computer it also prints a QR code to open it on your phone, and Settings shows one for whatever address you are using.

To run it from a clone instead: git clone https://github.com/Ki-Seki/pelican && cd pelican && npm ci && npm run build && npm link.

Keep it running. Pelican only answers while it runs. Start it at login with a launchd agent on macOS or a systemd user service on Linux, or in a tmux session.

Use it from your phone

Pelican listens on 127.0.0.1, so only your computer can reach it until you choose a way in, and every browser signs in, with the link Pelican printed or with a password. Whoever can use Pelican can run Claude Code as you, so pick a way in that keeps everyone else out.

Tailscale (recommended)

Your phone and computer join the same private network, and tailscale serve puts Pelican behind HTTPS, which notifications need.

tailscale serve --bg 7860    # https://<computer>.<tailnet>.ts.net

On the computer, open https://<computer>.<tailnet>.ts.net and paste the link Pelican printed to sign in. Then open Settings, tap Show code and scan it with your phone: it opens Pelican there, signed in. The code works once, for two minutes. Or set a password with pelican password and type it on the phone. If changes are refused with a 403, add the address to PELICAN_ALLOWED_ORIGINS.

An SSH tunnel

From a laptop, or a phone app that forwards ports (Termius, Blink): ssh -N -L 7860:127.0.0.1:7860 you@computer, then open the link Pelican printed.

Your own reverse proxy

Put Pelican behind Caddy or nginx with HTTPS and tell it the public address. Browsers sign in with the token or your password; if the proxy already authenticates, turn Pelican’s own sign-in off:

PELICAN_ALLOWED_ORIGINS=https://pelican.example.com pelican
PELICAN_ALLOWED_ORIGINS=https://pelican.example.com pelican --no-auth   # the proxy authenticates

With the proxy on the same computer, PELICAN_TRUSTED_PROXY=1 lets Pelican count failed sign-ins per client. Pelican works under any path prefix, so https://example.com/pelican/ is fine.

On the home network

pelican --host 0.0.0.0 prints a QR code for your phone and works across your Wi-Fi, but over plain HTTP: the sign-in travels in the clear and notifications are off. Prefer Tailscale.

Add it to your Home Screen

In Safari, Share → Add to Home Screen; in Chrome, Install app. Pelican then opens full screen, and on an iPhone notifications only work this way.

Using Pelican

Sessions

The list shows every Claude Code session on the computer, whichever app started it: the terminal, Claude Desktop, VS Code or Pelican. A session another app is working on shows Working in Claude Desktop (or the terminal, or your editor), and one waiting for you shows Needs you. A dot marks what changed since you last looked.

Search covers titles, folders and the latest reply. Filter by project; sessions started without a project share one Scratch filter, and runs in the system’s temp folder (usually started by another session) stay out of All unless the list’s options say otherwise. Group by time or by project, with detailed or compact rows, from the button next to the search.

Reading a session

Three views: each session keeps the one picked in its menu, and the others open in the one picked in Settings. Summary shows your prompts and Claude’s replies with the steps counted, Normal folds long runs of steps, Verbose opens every step and Claude’s thinking. Tool calls show what they did the way you would check it: diffs for edits, the command and its output, images. Plans, questions and the task list get their own cards; an Agent call opens the steps its subagent took.

The whole history is there: scroll up to the first prompt. A divider marks each compaction; open it to read the summary Claude carried on from. For a session running in Pelican, each turn shows its time, tokens and cost, and a ring shows how full the context is.

Talking to Claude

  • The first chip picks the model, the effort level (up to max), fast mode and ultracode; the second picks the permission mode: ask before acting, accept edits, plan first, auto, or bypass. Both belong to the session, which keeps them, Bypass included; a change reaches a Claude already at work from its next step. New sessions start with the model picked in Settings, asking before acting, and so does a branch.
  • Type / for commands and skills, @ for files, folders and subagents. Attach photos and files, or paste them.
  • Tap the microphone, where Send is when the box is empty, to dictate.
  • Enter sends on a computer and starts a new line on a phone; Settings changes that.

While Claude works

Approvals appear above the composer with the diff or the command: Allow, Always allow (Claude Code remembers the rule) or Deny with a note. Questions and plans are answered the same way.

A message you send while Claude works steers it: Claude reads it at its next step, as when you type in the terminal. Tap Steer next to Send to queue it instead, so it waits for the turn to end and starts the next one. Settings picks which comes first. Stop interrupts the turn.

! commands

Start a message with ! to run a command in the session’s folder, like Claude Code’s bash mode: !git log --oneline -5. The output lands in the conversation, and Claude reads it with your next message. Commands run in your login shell, without a terminal, for up to two minutes.

Changes and files

The folder button in a session’s header opens what is in its folder. Changes lists every file changed since the last commit with its line counts; open one for its diff. Files browses the folder; open a file to read it with highlighting, or Mention it in your message.

Visuals and pages

What Claude makes to be looked at is shown that way. Charts and diagrams it draws as Claude Desktop visuals appear in the conversation, a page or SVG it writes opens rendered (with its code a tap away, and full screen), html and svg blocks in a reply can be previewed, and files it sends you show as pictures, pages or documents. All of it runs in a sandboxed frame that cannot reach Pelican, your cookies or its API.

Rewind and branches

Tap one of your prompts for its actions. Rewind code puts the files Claude changed since that prompt back the way they were, after showing which ones; the conversation stays. Edit opens the prompt in place, images and all. Send replaces the last prompt in this session, as rewinding does in Claude Code; for an earlier one it makes a branch from just before it and sends the new text there, and the original stays. The session menu also has Branch (a full copy), Rename, Export as Markdown, Archive (off the list, under Archived; nothing else changes), Delete, and the command that continues the session in a terminal.

A session can be open in Claude Desktop or a terminal and in Pelican at once. Continue in one place: before it sends, Pelican catches up with what was said in the other app, but the other app does not see what you send here until the session is reopened there. Pelican says so the first time, and the session menu shows where else a session is open. Claude Desktop’s side chats are folded out of the list; the list’s options show them.

MCP servers, usage and background tasks

The session menu lists the session’s MCP servers and whether they connected; while Claude runs in Pelican, each can be turned off or reconnected. Settings shows your account and the plan’s usage limits as Claude Code reports them, and the session warns as a limit gets close. Commands and agents Claude runs in the background appear above the composer, each with a Stop.

Notifications, turned on in Settings, arrive when a turn finishes or Claude needs you; tapping one opens the session.

pelican token prints the link that signs a browser in (Pelican shows it at start only on a terminal, never in a log), and pelican token --reset makes a new token. pelican password sets a password, which replaces the token until pelican password --off removes it. A new token or password signs every browser out.

Security

Treat access to Pelican like SSH access: it can read your sessions and run Claude Code, and so commands, as you.

  • Every browser signs in, also on this computer. Pelican listens on 127.0.0.1 and asks for the access token in the link it prints, or for your password, so other accounts and programs on the computer get nowhere. The token is random and kept readable only by you; the password is set on the computer itself and kept as a scrypt hash. Failed sign-ins are limited to 10 per client and 30 in all every 10 minutes.
  • Cookies are HttpOnly and SameSite=Strict, signed with a secret that changes with the token or password.
  • Only Pelican’s own page. Its requests carry a header another site cannot add, requests a browser says come from another site are refused (reads too), and changes must come from Pelican’s origin or one you allowed. The server answers only to this computer’s names, loopback, *.ts.net and the names you configure (DNS rebinding), and only Pelican’s own origin may frame it.
  • What Claude writes stays on the screen. Images in a reply load only from Pelican; pages and visuals Claude makes render in a sandboxed frame that cannot reach Pelican and talks to no server but the public script and font CDNs.
  • Folders run nothing of their own until Claude has worked in them. Looking at a fresh clone loads only your user settings, not its hooks or MCP servers, and git runs with the repository’s own hooks, filters and helpers turned off.
  • The phone’s QR code carries a one-time code, good once for two minutes; the page never sees the token or your password, and the token is never written to a log.
  • --no-auth is for when something in front of Pelican authenticates. The demo signs no one in, so it stays on 127.0.0.1 unless you pass it.
  • No copies. Pelican reads Claude Code’s transcripts where Claude Code writes them. It stores uploads, push keys and subscriptions in its state folder, and sends nothing anywhere but your browser and, for notifications, your browser’s push service.

Report a vulnerability privately through GitHub security advisories.

How it works

  1. The web app talks to the server over REST and a WebSocket, which carries Claude’s reply as it is written, permission requests and status changes.
  2. To run a turn, the server starts Claude Code with the Agent SDK, resuming the session, and passes your approvals back. An idle process closes after a while; the next message resumes the session.
  3. Everything else comes from Claude Code’s own files. The transcripts in ~/.claude/projects, read incrementally and across compactions, give each session’s history, whichever app wrote it; they are followed while anyone watches. The process registry in ~/.claude/sessions tells which sessions another app is working on.

Compared with

There are good ways to reach Claude Code from a phone. What sets Pelican apart is that it works with the sessions you already have, and runs entirely on your computer.

  • Claude Code Remote Control (Anthropic) continues a session you start with claude --rc in the Claude app, through your claude.ai account. Pelican needs no flag and no account: every session is there, also ones started in Claude Desktop or your editor, and API keys and cloud providers work.
  • Happy is a polished native app that relays end-to-end encrypted sessions you start with happy instead of claude. Pelican has no relay and no wrapper; your phone talks to your computer directly, over your own network.
  • CloudCLI is a web UI for several coding agents, with a file tree, git and a terminal. Pelican does one agent, Claude Code, as far as it goes: steer and queue, rewind, branches, subagents, MCP, usage, the whole history across compactions, on a screen made for a phone.

Questions

Does it send my code anywhere?
No. Pelican talks to your browser and to Claude Code on the same computer. Claude Code talks to Anthropic as it always does.
Does it work with an API key, Bedrock or Vertex?
Yes: Pelican uses whatever Claude Code is set up with.
Can I use it while the same session runs in the terminal?
Yes. Pelican shows that another app is working on it and follows along. Sending from Pelican then starts a second Claude in that conversation, so wait for the other one to finish first.
Several computers?
Run Pelican on each; each is its own page. Add them all to your Home Screen.
Windows?
Pelican is developed on macOS and Linux. It should run on Windows, untested so far; reports are welcome.

Development

git clone https://github.com/Ki-Seki/pelican && cd pelican
npm ci
npm run dev          # server on :7860, web app on :5173, both reloading
npm test && npm run typecheck

npm run build && npm run demo serves the build with made-up sessions. The pictures come from npm run screenshots and node scripts/icons.mjs, and this site with its live demo from node scripts/site.mjs. More in CONTRIBUTING.md.
