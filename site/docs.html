Pelican docs

Every Claude Code session on your computer, on your phone. Pelican runs next to Claude Code and gives it a web app made for a phone; this page covers setting it up and everything it does.

Install

On the computer where you use Claude Code, with Node 22.12 or newer and Claude Code signed in (run claude once and log in, or set an API key the way Claude Code reads it). Pelican runs on macOS and Linux.

npm install -g pelican-cc
pelican

Pelican prints a link, http://localhost:7860/?token=…. Open it: it signs this browser in, and your sessions are there already. pelican token prints it again.

The install is about 150 MB, most of it the copy of Claude Code that the Agent SDK brings; Pelican runs that copy unless PELICAN_CLAUDE_PATH names another. The command is also called pelican-cc, for computers where Python’s Pelican already has pelican.

To look first, open the live demo, which needs nothing installed, or run npx pelican-cc --demo for the same made-up sessions on this computer (the same 150 MB download, the first time). To run Pelican from a clone instead: git clone https://github.com/Ki-Seki/pelican && cd pelican && npm ci && npm run build && npm link.

Keep it running

Pelican only answers while it runs. This keeps it running in the background, as a launchd agent on macOS or a systemd user service on Linux:

pelican service install

pelican service status shows how it is doing, pelican service restart restarts it, and pelican service uninstall removes it. pelican token prints the link that signs a browser in.

While Claude works, Pelican keeps the computer from going to sleep (PELICAN_KEEP_AWAKE=0 turns that off). A computer that is asleep answers nothing, though, so to reach Pelican while Claude is idle, keep the computer awake: on a Mac on power, with the lid open, caffeinate -s does it while it runs; on Linux, systemd-inhibit --what=sleep sleep infinity; or use your system’s power settings.

Update and remove

npm install -g pelican-cc@latest updates Pelican, and with it the copy of Claude Code it runs. Then restart it, with pelican service restart if it runs as a service. A page that was already open picks up the new app when it reloads.

To remove Pelican, run pelican service uninstall if you installed the service, then npm uninstall -g pelican-cc. Its own files stay until you delete them: rm -rf ~/.config/pelican ~/.local/state/pelican removes the token, the password hash, uploads and notification keys. Sessions started without a project keep their folders in ~/scratch. Your Claude Code sessions belong to Claude Code and stay where they are.

Use it from your phone

Pelican listens on 127.0.0.1, so only your computer can reach it until you choose a way in, and every browser signs in, with the link Pelican printed or with a password. Whoever can use Pelican can run Claude Code as you, so pick a way in that keeps everyone else out.

Tailscale (recommended)

Your phone and computer join the same private network, and tailscale serve puts Pelican behind HTTPS, which notifications need.

tailscale serve --bg 7860

It prints the address, https://<computer>.<tailnet>.ts.net. Run pelican phone with that address, as in pelican phone https://laptop.example.ts.net: it prints a QR code and a link that sign your phone in, once. Scan it with the phone’s camera, and Pelican opens there.

Or open the address on the computer, sign in with the link Pelican printed, open Settings and tap Show code. Or set a password with pelican password and type it on the phone. If changes are refused with a 403, add the address to PELICAN_ALLOWED_ORIGINS.

An SSH tunnel

From a laptop, or a phone app that forwards ports (Termius, Blink): ssh -N -L 7860:127.0.0.1:7860 you@computer, then open the link Pelican printed.

Your own reverse proxy

Put Pelican behind Caddy or nginx with HTTPS and tell it the public address. Browsers sign in with the token or your password:

PELICAN_ALLOWED_ORIGINS=https://pelican.example.com pelican

If the proxy already authenticates, add --no-auth to turn Pelican’s own sign-in off. With the proxy on the same computer, PELICAN_TRUSTED_PROXY=1 lets Pelican count failed sign-ins per client. Pelican works under any path prefix, so https://example.com/pelican/ is fine.

On the home network

pelican --host 0.0.0.0 prints a QR code for your phone and works across your Wi-Fi, but over plain HTTP: the sign-in travels in the clear and notifications are off. Prefer Tailscale.

Add it to your Home Screen

In Safari, Share → Add to Home Screen; in Chrome, Install app. Pelican then opens full screen, and on an iPhone notifications only work this way.

Using Pelican

Sessions

The list shows every Claude Code session on the computer, whichever app started it: the terminal, Claude Desktop, VS Code or Pelican. A session another app is working on shows Working in Claude Desktop (or the terminal, or your editor), and one waiting for you shows Needs you. A dot marks what changed since you last looked.

Search covers titles, folders and the latest reply. Filter by project; sessions started without a project share one Scratch filter, and runs in the system’s temp folder (usually started by another session) stay out of All unless the list’s options say otherwise. Group by time or by project, with detailed or compact rows, from the button next to the search.

Reading a session

Three views: each session keeps the one picked in its menu, and the others open in the one picked in Settings. Summary shows your prompts and Claude’s replies with the steps counted, Normal folds long runs of steps, Verbose opens every step and Claude’s thinking. Tool calls show what they did the way you would check it: diffs for edits, the command and its output, images. Plans, questions and the task list get their own cards; an Agent call opens the steps its subagent took.

The whole history is there: scroll up to the first prompt. A divider marks each compaction; open it to read the summary Claude carried on from. For a session running in Pelican, each turn shows its time, tokens and cost, and a ring shows how full the context is.

Talking to Claude

  • The first chip picks the model, the effort level (up to max), fast mode and ultracode; the second picks the permission mode: ask before acting, accept edits, plan first, auto, or bypass. Both belong to the session, which keeps them, Bypass included; a change reaches a Claude already at work from its next step. New sessions start with the model picked in Settings, asking before acting, and so does a branch.
  • Type / for commands and skills, @ for files, folders and subagents. Attach photos and files, or paste them.
  • Tap the microphone, where Send is when the box is empty, to dictate.
  • Enter sends on a computer and starts a new line on a phone; Settings changes that.

While Claude works

Approvals appear above the composer with the diff or the command: Allow, Always allow (Claude Code remembers the rule) or Deny with a note. Questions and plans are answered the same way.

A message you send while Claude works steers it: Claude reads it at its next step, as when you type in the terminal. Tap Steer next to Send to queue it instead, so it waits for the turn to end and starts the next one. Settings picks which comes first. Stop interrupts the turn.

! commands

Start a message with ! to run a command in the session’s folder, like Claude Code’s bash mode: !git log --oneline -5. The output lands in the conversation, and Claude reads it with your next message. Commands run in your login shell, without a terminal, for up to two minutes.

Changes and files

The folder button in a session’s header opens what is in its folder. Changes lists every file changed since the last commit with its line counts; open one for its diff. Files browses the folder; open a file to read it with highlighting, or Mention it in your message.

Visuals and pages

What Claude makes to be looked at is shown that way. Charts and diagrams it draws as Claude Desktop visuals appear in the conversation, a page or SVG it writes opens rendered (with its code a tap away, and full screen), html and svg blocks in a reply can be previewed, and files it sends you show as pictures, pages or documents. All of it runs in a sandboxed frame that cannot reach Pelican, your cookies or its API.

Rewind and branches

Tap one of your prompts for its actions. Rewind code puts the files Claude changed since that prompt back the way they were, after showing which ones; the conversation stays. Edit opens the prompt in place, images and all. Send replaces the last prompt in this session, as rewinding does in Claude Code; for an earlier one it makes a branch from just before it and sends the new text there, and the original stays. The session menu also has Branch (a full copy), Rename, Export as Markdown, Archive (off the list, under Archived; nothing else changes), Delete, and the command that continues the session in a terminal.

A session can be open in Claude Desktop or a terminal and in Pelican at once. Continue in one place: before it sends, Pelican catches up with what was said in the other app, but the other app does not see what you send here until the session is reopened there. Pelican says so the first time, and the session menu shows where else a session is open. Claude Desktop’s side chats are folded out of the list; the list’s options show them.

MCP servers, usage and background tasks

The session menu lists the session’s MCP servers and whether they connected; while Claude runs in Pelican, each can be turned off or reconnected. Settings shows your account and the plan’s usage limits as Claude Code reports them, and the session warns as a limit gets close. Commands and agents Claude runs in the background appear above the composer, each with a Stop.

Notifications, turned on in Settings, arrive when a turn you sent from Pelican finishes or Claude needs you there; tapping one opens the session.

Security

Treat access to Pelican like SSH access: it can read your sessions and run Claude Code, and so commands, as you.

  • Every browser signs in, also on this computer. Pelican listens on 127.0.0.1 and asks for the access token in the link it prints, or for your password, so other accounts and programs on the computer get nowhere. The token is random and kept readable only by you; the password is set on the computer itself and kept as a scrypt hash. Failed sign-ins are limited to 10 per client and 30 in all every 10 minutes.
  • Cookies are HttpOnly and SameSite=Strict, signed with a secret that changes with the token or password.
  • Only Pelican’s own page. Its requests carry a header another site cannot add, requests a browser says come from another site are refused (reads too), and changes must come from Pelican’s origin or one you allowed. The server answers only to this computer’s names, loopback, *.ts.net and the names you configure (DNS rebinding), and only Pelican’s own origin may frame it.
  • What Claude writes stays on the screen. Images in a reply load only from Pelican; pages and visuals Claude makes render in a sandboxed frame that cannot reach Pelican and talks to no server but the public script and font CDNs.
  • Folders run nothing of their own until Claude has worked in them. Looking at a fresh clone loads only your user settings, not its hooks or MCP servers, and git does not run there. Where Claude has worked, git runs with hooks, the file-system monitor, external diffs and text converters turned off.
  • The phone’s QR code carries a one-time code; the page never sees the token or your password, and the token is never written to a log.
  • --no-auth is for when something in front of Pelican authenticates. The demo signs no one in, so it stays on 127.0.0.1 unless you pass it.
  • No copies. Pelican reads Claude Code’s transcripts where Claude Code writes them. It stores uploads, push keys and subscriptions in its state folder, and sends nothing anywhere but your browser and, for notifications, your browser’s push service.

The whole model is in SECURITY.md. Report a vulnerability privately through GitHub security advisories.

How it works

  1. The web app talks to the server over REST and a WebSocket, which carries Claude’s reply as it is written, permission requests and status changes.
  2. To run a turn, the server starts Claude Code with the Agent SDK, resuming the session, and passes your approvals back. An idle process closes after a while; the next message resumes the session.
  3. Everything else comes from Claude Code’s own files. The transcripts in ~/.claude/projects, read incrementally and across compactions, give each session’s history, whichever app wrote it; they are followed while anyone watches. The process registry in ~/.claude/sessions tells which sessions another app is working on.

Compared with

There are good ways to reach Claude Code from a phone. What sets Pelican apart is that it works with every session you already have, from any app, and puts nothing between your phone and your computer. As each project documents it, checked on 5 November 2026:

  • Remote Control (Anthropic) connects the Claude app or claude.ai to a session on your computer: run /remote-control in it, start it with claude --remote-control, or turn on Enable Remote Control for all sessions in /config (Claude Desktop and VS Code have the same switch). It forwards permission prompts and questions to your phone with a push, which Pelican cannot do for a session another app is running. It needs a Claude plan; API keys, Bedrock, Google Cloud’s Agent Platform, Microsoft Foundry and LLM gateways are not supported, and on Team and Enterprise an Owner turns it on. Its traffic goes through Anthropic, which stores the transcript while a session is connected, so organizations with Zero Data Retention or the HIPAA configuration cannot use it. From the app you cannot pick Bypass, and a line starting with ! goes to Claude as a message.
  • Yep Anywhere is a web interface for Claude Code and Codex on the Agent SDK, with push notifications and no accounts. It resumes sessions started in the CLI, VS Code and desktop apps, and besides direct access it offers a free relay, end-to-end encrypted.
  • Happy and HAPI wrap the CLI: you start happy claude or hapi claude instead of claude, and continue from native apps (HAPI also has a web app) through a relay, end-to-end encrypted. Both run Codex and other agents too.
  • CloudCLI is a web UI for Claude Code, Cursor CLI and Codex, with a file explorer, git and a shell. It finds every session in ~/.claude; you run it on your network, or use CloudCLI Cloud, a hosted environment.
  • SSH and tmux need nothing new on the computer: run claude inside tmux and reach it from an SSH app. Pelican is for what a terminal on a phone does badly: long transcripts, diffs, approvals in one tap, notifications, charts and pages, and history across compactions.

Questions

Does it work with my Claude plan?
Pelican runs Anthropic’s own Claude Code, unmodified (the copy the official Agent SDK ships, or the one PELICAN_CLAUDE_PATH names), on your computer, signed in the way you signed in to claude. It never sees, stores or forwards your credentials, puts no service in between, and serves only you: don’t open your Pelican to other people. Signed in with a plan, what you send from Pelican is Agent SDK usage, which draws from your plan’s limits, as Anthropic’s help center says; Anthropic paused a planned change to that on 15 June 2026, so their page has the latest. An API key, Bedrock, Google Cloud or Microsoft Foundry are billed as usual. Anthropic’s rules: authentication and credential use, and using the Agent SDK with your Claude plan. Checked on 5 November 2026.
Why not Remote Control?
Use Remote Control if you are on a Claude plan and want to answer, from your phone, the prompt waiting in your terminal: Pelican cannot. Pelican shows every session on the computer without turning anything on, keeps nothing on anyone’s servers, and works with any login, API keys and cloud providers included. The comparison has the details.
Can I approve a prompt waiting in my terminal?
No: that prompt belongs to the Claude running in the terminal, so answer it there, or use Remote Control. Pelican shows the session as it works, and once it is idle you can continue it here. Work you start or continue in Pelican asks you in Pelican, with a notification.
Why not SSH and tmux?
That works, and needs nothing new on the computer. Pelican is for what a terminal on a phone does badly: long transcripts, diffs, approvals in one tap, notifications, charts and pages, and history across compactions.
What happens when my computer sleeps?
A computer that is asleep runs nothing: Pelican does not answer, and Claude does not work. While Claude works, Pelican keeps the computer awake; to reach Pelican at any time, keep the computer from sleeping, as Keep it running shows.
Does it send my code anywhere, or phone home?
No. Pelican is free and MIT licensed, with no account and no telemetry. It talks to your browsers and to Claude Code on the same computer and, if you turn notifications on, to your browser’s push service, with the content encrypted. Claude Code talks to Anthropic, or your provider, as it always does.
Why is the install about 150 MB?
The official Agent SDK, which Pelican runs Claude Code through, brings its own copy of Claude Code; Pelican itself is under 1 MB. The live demo needs no install at all.
Does it work with an API key, Bedrock or Vertex?
Yes: Pelican uses whatever Claude Code is set up with, Microsoft Foundry and LLM gateways included.
Can I use it while the same session runs in the terminal?
Yes. Pelican shows that another app is working on it and follows along. Sending from Pelican then starts a second Claude in that conversation, so wait for the other one to finish first.
Several computers?
Run Pelican on each; each is its own page. Add them all to your Home Screen.
Windows?
Pelican runs on macOS and Linux. Native Windows does not work yet: ! commands and the status of other apps’ sessions assume a Unix system. WSL is Linux, so Pelican should run there, untested so far; reports are welcome.

Development

git clone https://github.com/Ki-Seki/pelican
cd pelican
npm ci
npm run dev

npm run dev runs the server on port 7860 and the web app on port 5173, both reloading on change. npm test && npm run typecheck checks a change, and npm run build && npm run demo serves the build with made-up sessions. The pictures come from npm run screenshots and node scripts/icons.mjs, and this site with its live demo from node scripts/site.mjs. More in CONTRIBUTING.md.
