Pelican docs

Every Claude Code session on your computer, on your phone. Pelican runs next to Claude Code and gives it a web app made for a phone; this page covers setting it up and everything it does.

Install

On the computer where you use Claude Code, with Node 22.12 or newer and Claude Code signed in (run claude once and log in, or set an API key the way Claude Code reads it). Pelican runs on macOS and Linux.

npm install -g pelican-cc
pelican

Pelican prints a link, http://localhost:7860/?token=…. Open it: it signs this browser in, and your sessions are there already. pelican token prints it again, and pelican --open opens Pelican in this computer’s browser.

The install is about 150 MB to download and about 400 MB on disk, most of it the copy of Claude Code that the Agent SDK brings. The command is also called pelican-cc, for computers where Python’s Pelican already has pelican; if npm stops with EEXIST on bin/pelican, use npx pelican-cc, or install into another prefix.

To look first, open the live demo, which needs nothing installed, or run npx pelican-cc --demo for the same made-up sessions on this computer (the same 150 MB download, the first time). To run Pelican from a clone instead: git clone https://github.com/Ki-Seki/pelican && cd pelican && npm ci && npm run build && npm link.

Which Claude Code runs

Pelican runs the Claude Code its Agent SDK brings, at the version Pelican was tested with: the SDK is pinned, and the package ships the exact dependency tree its tests ran on. The start banner says which Claude Code runs and whether it is signed in; if it is not, pelican login signs it in with Claude Code’s own login. Settings › About shows the version too, and pelican --version prints the versions of Pelican, Claude Code, the Agent SDK and Node on one line, the line to put in a bug report.

Each Pelican release moves to the newest Agent SDK once the tests pass, so updating Pelican is how its Claude Code gets updated. When the claude in your terminal is newer, the start banner and Settings › About say so. To run that one instead, start Pelican with PELICAN_CLAUDE_PATH="$(command -v claude)".

Keep it running

Pelican only answers while it runs. This keeps it running in the background: it starts when you log in, and again if it stops.

pelican service install

On macOS it is a login item (a launchd agent), with its log in ~/Library/Logs/pelican.log. On Linux it is a systemd user service: journalctl --user -u pelican shows its log, and loginctl enable-linger keeps it running after you log out. pelican service status shows how it is doing, pelican service restart restarts it, and pelican service uninstall removes it. The service needs Pelican installed with npm install -g, not run through npx. Variables that look like secrets, such as ANTHROPIC_API_KEY, are not copied into it, and its log never holds the sign-in link: pelican token prints that.

While Claude works, in Pelican or in another app, Pelican keeps the computer from going to sleep on its own (PELICAN_KEEP_AWAKE=0 turns that off). A closed laptop lid still sleeps, unless the laptop is on power with a display attached. A computer that is asleep answers nothing, so to reach Pelican while Claude is idle, keep the computer awake: on a Mac on power, with the lid open, caffeinate -s does it while it runs; on Linux, systemd-inhibit --what=sleep sleep infinity; or use your system’s power settings.

Update and remove

Settings says first thing when a newer Pelican is out, with what changed in it, and its gear in the session list has a dot meanwhile. Pelican asks npm’s registry once a day, and when Settings opens: the registry npm install -g uses, as your npm settings name it, never one a project’s .npmrc names in the folder Pelican was started from. Offline, it says nothing. Updating Pelican also updates the copy of Claude Code it runs.

Where you installed Pelican with npm install -g, into npm’s global folder, Update does it all: npm installs that very version first into a folder of its own, where Pelican checks that it starts, then over your install, with the same prefix, checking each download against the registry’s integrity; then Pelican starts again, through launchd or systemd when it runs as a service, and in its own place, in the same terminal, when you started it there. Open pages reconnect by themselves, show the new version and say so. If anything fails, the version that ran goes on running, and Settings says what failed.

An update restarts Pelican, which ends Claude’s processes, background tasks and terminals, and the messages queued for the end of a turn, which are not sent; transcripts, files, pins, settings and drafts stay. So while anything runs (a session working or waiting for you, messages queued for the end of its turn, background agents, workflows or commands, a program in a terminal, a ! command), Settings lists it first, with Update now and Update when idle, which waits until nothing has run for a minute; Settings shows it waiting, with Cancel. While Pelican replaces your install and starts again, nothing new starts: a change, or anything that would start Claude Code, git, gh, a terminal or a search, waits for the new version.

Where Pelican cannot update itself, Settings shows the command to run instead, and why: run through npx, pnpm dlx or bunx, npx pelican-cc@, pnpm dlx pelican-cc@ or bunx pelican-cc@ with the new version, to start Pelican with once you stop it; from a clone, git pull and a build; installed by pnpm, Yarn, Bun or Volta, that tool’s command; installed into another prefix than npm’s, such as one a script of your own keeps, npm install -g --prefix with it, for you or your script to run; in a global folder root owns, sudo npm install -g. Pelican never installs over a version something else keeps, and never runs sudo. By hand, npm install -g pelican-cc@latest updates Pelican; then restart it, with pelican service restart if it runs as a service.

To remove Pelican, run pelican service uninstall if you installed the service, then npm uninstall -g pelican-cc. Its own files stay until you delete them: rm -rf ~/.config/pelican ~/.local/state/pelican removes the token, the password hash, uploads, notification keys, the folders you trusted, and your pins and archive. Sessions started without a project keep their folders in ~/scratch. Your Claude Code sessions belong to Claude Code and stay where they are.

Use it from your phone

Pelican listens on 127.0.0.1, so only your computer can reach it until you choose a way in, and every browser signs in. Whoever can use Pelican can run Claude Code as you, so pick a way in that keeps everyone else out.

Tailscale (recommended)

Your phone and computer join the same private network, and tailscale serve puts Pelican behind HTTPS, which notifications need. With Tailscale on both:

tailscale serve --bg 7860
pelican phone

pelican phone finds the address tailscale serve gave Pelican, checks that it reaches this very Pelican, and prints a QR code. Scan it with the phone’s camera: Pelican opens there, signed in. The code works once, for two minutes; press Enter for a new one. On a Mac with only the Tailscale app, tailscale is not a command in your terminal; run pelican phone, and it prints the command with the app’s own path.

Once Pelican knows the phone’s address, its start banner shows the QR code, and so does Settings › On your phone on the computer. To give the address yourself, run pelican phone https://laptop.example.ts.net, or start Pelican with PELICAN_PUBLIC_URL set to it. Or set a password with pelican password and type it on the phone.

An SSH tunnel

From a laptop, or a phone app that forwards ports (Termius, Blink): ssh -N -L 7860:127.0.0.1:7860 you@computer, then open the link Pelican printed.

Your own reverse proxy

Put Pelican behind Caddy or nginx with HTTPS, and tell it the public address:

PELICAN_PUBLIC_URL=https://pelican.example.com pelican

Pelican then answers to that name and takes changes from it, and pelican phone makes its QR codes for it. If the proxy already authenticates, add --no-auth to turn Pelican’s own sign-in off. With the proxy on the same computer, PELICAN_TRUSTED_PROXY=1 lets Pelican count failed sign-ins per client. Pelican works under any path prefix, so https://example.com/pelican/ is fine.

On the home network

pelican --host 0.0.0.0 prints a QR code for your phone and works across your Wi-Fi, but over plain HTTP: the sign-in travels in the clear and notifications are off. Prefer Tailscale.

Add it to your Home Screen

In Safari, Share → Add to Home Screen; in Chrome, Install app. Pelican then opens full screen, and on an iPhone notifications only work this way.

Using Pelican

Sessions

The list shows every Claude Code session on the computer, whichever app started it: the terminal, Claude Desktop, VS Code or Pelican. A dot marks what changed since you last looked, and a bar marks the session that is open. A session’s title is the name you gave it or the one Claude Code wrote; without one, the text of a prompt, cut to one line. The browser tab shows the open session and how many sessions need you.

Search covers titles, folders and the latest reply. Filter by project; sessions started without a project share one Scratch filter, and runs in the system’s temp folder (usually started by another session) stay out of All unless the list’s options say otherwise; a folder there that you started a session in from Pelican (a checkout in /tmp, picked with Browse folders) is a project like any other, its sessions listed and the folder offered again under New session. Group by time or by project, with detailed or compact rows, from the button next to the search. Long lists load as you scroll, and a row opens in a new tab with ⌘-click (Ctrl-click).

A session whose turn is over but whose background work still runs shows how much, as 2 in background with a steady dot, among the active ones; it says Working again when Claude takes up what they found. A session Claude Code stopped before it could reply says why instead of a reply, such as Stopped: not signed in.

To keep a session at the top of the list, pin it: on a phone, swipe its row a little to the left and tap Pin; on a computer, pick Pin in the row’s ⋯, which shows in place of its time when you point at the row; or use Pin in the session menu. Pinned sessions lead the list under Pinned, however it is grouped, and under their project’s filter; each keeps its status and its earlier runs. To archive a session, swipe its row all the way to the left, tap Archive beside Pin, or pick Archive in its menu. A row takes no swipe to the right, which in Safari is Back, nor one that starts at the very edge of the screen, which the browser keeps for itself, nor one while text is selected. Archived sessions wait under the Archived filter, to be unarchived the same way. Undo shows for five seconds after either, whichever way you did it. Archiving a session takes it off the list and unpins it; nothing else changes. Pins and the archive are Pelican’s own, the same on your phone and your computer, and apart from Claude Desktop’s: a session pinned in Desktop is not pinned here.

+ opens an empty session in your latest project, or the project the list shows, or a new folder under Scratch, ready to type. Tap the folder under What should Claude do? to start somewhere else.

Sessions another app is running

Pelican sees every session Claude Code runs on the computer. One that another app is working on says Working in Claude Desktop (or the terminal, or VS Code), in the list and in its header, and you can follow it as it works. One that waits for you there, at a permission prompt or a question, says Needs you in the terminal, and if the wait lasts about 20 seconds your phone gets one notification; answer at the keyboard first and nothing is sent. Pelican cannot answer that prompt for you: answer it in that app, or with Remote Control.

The message box says what sending would do, for example Working in the terminal · a message starts a second Claude. A session another app has open but idle says so at the foot of the session menu. Continue a session in one place at a time: before it sends, Pelican catches up with what was said in the other app, but the other app does not see what you send here until the session is reopened there. Side chats, Claude Desktop’s and Pelican’s, are kept out of the list; Side chats in the list’s options shows them.

Where every action is

Each thing you act on has one short list of actions, in Claude Desktop’s words and order, and every way to it shows the same list: a session, your prompt, Claude’s reply, a step, and a file’s path. On a computer, right-click the thing, or use its ⋯ where it has one; Desktop’s key for an action shows faintly beside it. On a phone, press and hold the thing for half a second: a session’s row, your prompt, a step or a path rises over a sheet of its actions. A long press on Claude’s words stays your phone’s own, for selecting text.

  • The session menu is the session’s title, with ▾: Rename, Pin, Side chat, Fork (a full copy), Copy resume command (to carry on in a terminal), Export (as Markdown), Transcript view, Archive and Delete, which asks first and waits while Claude works. Its foot says when the session started, in which app it is open as well, if one has it, and its ID, to copy. A row of the list has the same menu from its ⋯, a right-click or a long press, without the view and the keys, which are the open session’s. On a phone the menu starts with Changes, Files and Terminal.
  • The header has, on a computer, three quiet buttons: Changes, with the lines changed (+31 −2), Files and Terminal, each with its name and key when you point at it. A phone has one button, the lines changed, or a folder while nothing has.
  • Your prompt: on a phone, a tap shows Copy, Rewind to here and Fork from here under it, and a long press has Quote and Select text as well; on a computer, Copy, Rewind to here and Fork from here show beside it when you point at it, and a right-click has the rest. A left swipe quotes it.
  • Claude’s reply has Copy, ⋯ and its time under it, always on a phone, and on a computer when you point at it: Copy, Fork from here, ⋯, the model and the time. Its ⋯ has Copy message, Copy message as Markdown, Start a side chat, Quote message, Rewind to here and Fork from here, and the turn’s model, time, tokens and cost at its foot. A right-click puts what you clicked first: Copy and Quote selection for text you selected, Copy code on a code block, a path’s own menu on a path; a link or a picture keeps the browser’s own menu.
  • A step: a command has Copy command, Run in terminal, Copy output, Start a side chat and Quote output; an agent View output; a step on a file has its path’s menu. On a computer it has a ⋯ when you point at it. A ! command has a command’s list too. Run in terminal asks first, in place, as a code block’s does, showing the whole command rather than the step’s description of it, and is offered for a command that shows all it holds, as a code block’s is; not on a step you denied, nor on a subagent’s or a workflow’s steps, and on a PowerShell step only where the terminal runs PowerShell.
  • A path, in a reply, a step, a row of Changes or Files, or under a file’s ⋯, opens its file with a tap or a click, and its menu is Desktop’s: Attach as context (the file goes with your next message, as @"path"), Copy its absolute or relative path or its name, Open in Changes for a file with changes, Open in Files and Download file; a folder has Open in terminal.
  • The message box’s + has Add files or photos, Commands, Files and agents, Shell command and the session’s MCP servers.
  • Context, the ring by Send, shows how full the context window is, with Compact, what the whole session used, your plan’s limits, and Usage and activity. On a phone it shows once a turn has run, faint and without its number below 60%.
  • One list of commands sits behind / in the message box and, on a computer, ⌘K (Ctrl K): this session’s actions by Claude Code’s names (/btw, /branch, /rewind, /rename, /export, /diff, /context, /mcp, /model, /usage), then Pelican’s (Pin, Archive, Files, Terminal, New session, Settings), then Claude Code’s commands and skills. One of your own commands with the name of one of Pelican’s is yours: /export then runs it, and Pelican’s Export stays in the list by its name. In ⌘K’s list, typing a session’s name finds it too.

On a computer the session list hides with its button at its top, or ⌘B (Ctrl B), as in Claude Desktop, and the browser remembers it; the conversation then takes the whole width, with the button first in its header. Point at the window’s left edge, or at that button, and the list comes over the conversation until the pointer leaves it, you pick a session, or Esc; ⇧⌘K brings it to search. Between 1024 and 1279 pixels wide, a pane beside the conversation hides the list the same way, and ⌘B or the button floats it over the conversation, which keeps its room, until ⌘B again, Esc, a click outside it or a pick. On a phone, Back (Android’s, or the browser’s) closes the sheet or menu that is open, and goes no further.

Reading a session

Three views, as in Claude Desktop: Normal folds the steps and shows the replies whole, Thinking adds Claude’s thinking, and Verbose opens every step. Each session keeps the one picked in its menu; the others open in the one picked in Settings, and Ctrl O steps through them. Tool calls show what they did the way you would check it: diffs for edits, the command and its output, images. Plans and questions get their own cards, with what you answered under them. Claude’s to-do list is one line, Tasks · 1 of 4 done, which opens to the list as it was then; while there is work left, the bar above the message box shows where it stands, the task under way first; an Agent call opens the steps its subagent took, and a workflow is a card with its phases and agents (below).

A file a step names opens at its line, where a read began or an edit changed it, and so does a path:line in a reply (also :7-8 and #L3-L9), when the file is in the session’s folder. Under a turn that edited files, 3 files changed opens what that turn changed.

A session opens at its newest message, and while Claude works the view follows what it writes. Scroll up and it stays where you are, with a round arrow to jump back to the end. The whole history is there, up to the first prompt; a divider marks each compaction, and opens to the summary Claude carried on from. Long prompts fold after about twelve lines, and files you sent show as chips that open them. Code shows with its language and a Copy button, highlighted in the common languages.

For a session running in Pelican, the last reply’s ⋯ has that turn’s time, tokens and cost, and a ring next to Send shows how full the context is. The cost is left out for Claude plans, whose usage limits Context and Usage and activity show instead, and for the first turn after a session is resumed. When a request fails, one line says why in plain words: the API is overloaded, the conversation is too long, Claude Code is not signed in (run claude and /login), or the usage limit was reached, and when it resets. At the end of the conversation it offers the next step: Retry sends the prompt again with its files, and Compact sends /compact when the conversation is too long.

Talking to Claude

  • The first chip picks the model, then the effort level (up to max), Fast mode and Ultracode, as Claude Code’s /model does; the second picks the permission mode. Both belong to the session, which keeps them; a change reaches a Claude already at work from its next step.
  • Type / for the list of commands, @ for files, folders and subagents, or pick them from +. Commands that only work in a terminal, such as /exit or /theme, are left out. /clear, /reset and /new start a new session in the same folder with the same settings, Bypass aside.
  • Attach photos and files with + (⌘U, Ctrl U), paste them, or drop them anywhere on the conversation. Pictures the API cannot take as they are, such as HEIC or SVG, go to Claude as files to read.
  • Select text in a reply, your prompt or a step’s output for Claude Desktop’s two: Start a side chat (Send to side chat once one is open), which opens the side chat with the passage attached, and Quote. On a computer they sit above the selection a moment after you let go, and ↵ quotes; Quote opens a note box above the selection, as in Claude Desktop, where ↵ adds the quote with your note (or as it is, without one; if Settings has Enter start a new line, ↵ does that here too, and Add adds), ⌘ Enter (Ctrl Enter) sends it now, a steer while Claude works, and Esc lets it go. A note half written stays when you look at another session and come back. ⇧⌘L (Ctrl Shift L) quotes a selection without a note. On a phone the pair sits above the message box once the selection rests, clear of the system’s own menu; Quote puts the passage in the box with Add a note, and the keyboard comes up only when you tap that. Swiping a paragraph, a prompt or a command left quotes it too. Lines of a file are quoted from Files.
  • What goes with your next message waits above the box as chips, each kind told apart: a quote, in quotation marks; a quote with a note, as its note; a line comment, where it is and what you said. Click or tap one to read it whole, change its note, show it where it came from, or remove it. A / or ! command leaves them for the next message, and a message that does not go gives them back as they were.
  • Pelican writes them as Claude Desktop does, so Desktop and the terminal see your quotes as replies, and Pelican shows Desktop’s as quotes: a quote with a note as a <!-- reply --> block, a quote without one as an <!-- attach --> block (lines of a file with their path and lines, the terminal’s with its tab), and a line comment as In `src/app.ts` at line 12: with the code under it. As in Desktop, keys and tokens in a quote are masked, a quote is cut at 1,500 characters (the terminal’s keeps its end), an @ that would mention a file becomes ＠, Claude Code’s own tags in a line comment’s code (such as <system-reminder>) are escaped so the code cannot speak as Claude Code, and a message holds up to 99 quotes with a note.
  • Tap the microphone, where Send is when the box is empty, to dictate with your browser’s dictation.
  • Enter sends on a computer and starts a new line on a phone; Settings changes that. ⌘ Enter (Ctrl Enter) always sends, and the Enter that picks a Chinese, Japanese or Korean word never does.
  • What you type is kept for each session, attached files, quotes with their notes and line comments included, until you send it: leaving the chat, opening another session or reloading the page keeps it. Signing out forgets it. A message that does not go, the computer out of reach, comes back to the box with its files, above anything you typed since; a ! or / command comes back only into an empty box, and otherwise waits above it with Put back, as does a message that comes back while you type a command, its files waiting with it. A command never takes words or files that are not its own: where the two cannot share the box, Put back swaps them, and what was in the box waits in its place, Set aside.

Permission modes

The mode decides what Claude may do without asking. The names are Claude Code’s:

ManualAsks before edits and commands.
Accept editsEdits files, and runs mkdir, mv, rm and the like, in the session’s folder without asking.
PlanReads and plans; changes nothing until you approve the plan.
AutoRuns what it needs, with Claude Code’s safety checks in the background, on the models that have it.
Bypass permissionsRuns everything without asking. Only for a machine that holds nothing you would miss.

New sessions start in the mode Claude Code starts them in: the permissions.defaultMode of its settings (a folder’s own settings count once the folder is trusted), and where no file names one, Auto, as the terminal does, or Manual on a model without Auto. As in Claude Code, Auto and Bypass count only from your own or managed settings, never from a folder’s, whose Bypass starts in Manual. Settings › New sessions start with picks Manual, Accept edits, Plan or Auto, and saves it in your Claude Code settings, as /config does; it never saves Bypass. Where your own settings make Bypass the default, new sessions start in it, as in Claude Code, and Settings and the new session say so. A branch, an edited earlier prompt or a /clear of a session in Bypass starts in the mode a new session would.

A session in Claude Code’s Don’t ask mode keeps it and shows it; Pelican does not offer it. When the mode changes without being picked in Pelican, for example when Claude leaves Plan, a short line in the conversation says so.

While Claude works

Approvals appear above the message box with the diff or the command, in Claude Code’s own words, saying which subagent or MCP server asks. Several come one at a time, marked 1 of 3. Allow lets this one through. The button next to it says what it saves and where, as Claude Code would: Always allow npm test * in this project (kept in the repository’s .claude/settings.local.json), Allow all edits this session (the session switches to Accept edits) or Allow access to ~/data for this session; it is left out when Claude Code would allow more than was asked. Deny works like Claude Code’s No: without a note, Claude stops and waits for you; with one, Claude carries on with what you said. Characters that hide text or turn it around show as ⟨U+202E⟩, with a warning, and so does a space other than a plain one in a command, which a shell takes as part of a word: echo done⟨U+00A0⟩# … reads as a comment but runs. Pelican leaves such a space as it is only where it finds it in quotes, the body of a heredoc or a comment, of the command or of a script the command hands a new shell (bash -c, ssh, a heredoc or a pipe into sh, a script it writes with a redirection or tee and runs, a file a shell reads as it starts, and the like), as it does in a file’s name; quoted text with a $(, a ${ or a backquote in it counts as a word. A command that uses what can run text later in its own shell (eval, source, trap, an alias, read, declare, zsh’s (e) and $~x, setopt, arithmetic on a variable it sets to anything but a number, and the like, by its name in any case, as a Mac runs READ as read) is one it cannot tell, and so is one that runs a script by a path that is not plain text (bash "$t") or from a folder it writes into, a command longer than 64 KB, and one that would take more than a fixed time and memory to read. Where it cannot tell, it writes out every one. A script another program writes by itself (with sed’s w, sort -o, perl or python) is not followed, nor a string a program runs in a shell of its own, such as python’s os.system. In PowerShell, which takes such a space for a space, it shows as it is, unless the command hands a script to bash, sh, wsl or ssh.

A plan can be approved into Auto (where the model has it), Accept edits or Manual, or sent back with Keep planning. Questions show their short header and a preview of the option you pick; on a computer the card takes the keys as it comes, unless you are typing, and 1 to 9 pick an option by the number shown beside it, as in Claude Desktop, while a letter starts your own answer under Other; after a pick the next question comes into view. A question of one choice takes a pick or your own words, never both, as in Desktop. An MCP server that asks for something gets a card to answer: a short form, or a page to open to sign in.

However little room there is above the message box (a pane open beside the conversation, a phone’s keyboard up, a phone on its side), a card keeps its buttons, Allow and Deny, Answer and Skip, Approve, in view at its foot and its title at its head, with what it asks about scrolling between them; the message box, Send, Stop and the model and mode stay in view under it. While a card waits, Claude’s task list and what runs in the background fold into one line under it, so its buttons sit near the thumb; a tap, or ⌃B, unfolds them.

While Claude works, Send sends a message now: Claude reads it at its next step, as when you type in the terminal. A quiet line above what you typed says so, and offers the other way beside it, Queue for later, a finger’s size on a phone; on a computer where Enter sends, ⌘ Enter (Ctrl Enter) does the same, as in Claude Desktop. Settings › While Claude works, Send makes Queues for later what Send does instead, and the line then offers Send now. Queued messages wait above the message box, where a tap takes one back to edit and × removes it, and go to Claude together when the turn ends, also after Stop. Stop shows while Claude works, beside Send once you have typed something; it, or Esc, ends the turn but leaves background agents and commands running, as Esc does in the terminal.

Notifications, turned on in Settings, say what Claude wants (the command, the file, the question) and, when a turn ends, the first line of the reply; tapping one opens the session. Where the device shows buttons on notifications (Chrome on a computer or Android, not iPhone), a command a notification shows whole has Allow, for this once, and Deny, which stops Claude as Deny does here: printable ASCII with one space between words, on one line, short enough for two lines of the narrowest notification, about 50 characters and fewer when they are wide. On Android, whose pop-up shows one line of a notification beside the buttons, the command must fit that one line, about 20 characters. A notification shows the command itself, never Claude’s description of it, and offers no buttons for what it might not show in full: a longer command, one with any other character, an edit or another tool opens the session, as questions and plans do. They come for the work you send from Pelican, and once when another app’s session has waited for you about 20 seconds. A new token or password stops them on every device, and signing out stops them on that one.

! commands

Start a message with ! to run a command in the session’s folder, like Claude Code’s bash mode: !git log --oneline -5. Its output shows as it comes, with how long it has run and Stop, which ends everything it started; once it ends, the end of the output stays in view, and Show all shows the rest. When it ends, Claude reads the output and answers, as in the terminal, unless your Claude Code settings set respondToBashCommands to false; that answer is a turn, like a prompt. Claude gets the output as Claude Code’s bash mode gives it: stdout and stderr together, up to 30,000 bytes or what bashOutputMaxChars sets; where that is unset, BASH_MAX_OUTPUT_LENGTH sets how much Claude Code reads back (1 to 150,000 bytes), of which Claude gets at most 30,000 characters inline. Past that, for a command that went well, Claude gets its start and where it was saved, up to 64 MB, in the session’s tool-results folder, which Show all reads; a command that failed is cut there, and says Failed once it is in the conversation. Exit code 1 from grep, diff, test or find is an answer, as in Claude Code, when that command is the last statement as Claude Code’s parser splits the line, which keeps a subshell or a { } group whole; a command in backquotes where a command would start counts too, such as `grep x f`. A command you stop gets no answer. Commands run in your login shell, without a terminal, for up to 30 minutes; one still running when Pelican stops gets up to 15 seconds to tidy up (Ctrl C again ends it at once). Pelican writes commands into the transcript as Claude Code does, so the terminal and Claude Desktop show them, and Pelican shows the ones run there.

On a phone, where this view covers the box, its foot says what waits.

Terminal

A terminal runs your login shell on the computer, in the session’s folder, as Claude Desktop’s does: with the environment Claude Code has there, so npm test and git status see the files Claude is editing, and git by hand goes there. The Terminal tab of Changes and files holds the folder’s terminals, and Ctrl ` (on a Mac too) shows it, or hides it again when you press it there; Ctrl Shift ` starts a new one, as in Claude Desktop. The first terminal starts when the tab first shows; + starts another, and Open in terminal, at the top of a folder in Files or in a folder’s menu, a path’s in a reply included, starts one in that folder. Each tab is named after the program in front of it, such as zsh, npm or vim. End hangs the one shown up, as closing a window does, asking first while a program runs in it, also a job left in the background (running or stopped), but not for what your prompt keeps running for itself, such as powerlevel10k’s gitstatusd or the worker of pure’s prompt.

On a computer you type straight into the terminal, with input methods such as Chinese pinyin, the emoji picker and dictation too. Select text there for Quote (⇧⌘L, Ctrl Shift L) or Copy (off a Mac, Ctrl C copies a selection too), hold ⌘ (Ctrl) and click to open a link, which says where it goes at the foot of the screen as you point at it (on a phone a tap asks first, saying where it goes, and opens it with Open), as a program’s link can read as any words, and use Ctrl and the wheel, or a pinch, to change the text size. A right-click opens Claude Desktop’s terminal menu: Quote and Copy what is selected, Paste, Select all and Clear terminal, which clears the screen and what scrolled off it, as clear does, on every page that shows the terminal and in the computer’s copy, so a reload shows it cleared; a program in front of the shell, such as vim or htop, draws its screen again, as after Ctrl L. On a phone a tap never raises the keyboard. You type in the line under the screen, with the phone’s own keyboard, so dictation and input methods such as Chinese pinyin work, and Enter sends the line; two spaces stay two spaces, not the period a phone’s keyboard makes of them, and while you type, the screen takes the room of the header and tabs above it. On a phone on its side the screen has that room whether you type or not, about a dozen rows, and a tap on it shows the header and tabs again, or folds them, and does nothing else: what comes back takes no tap for half a second, so neither that tap nor one made at once lands on End or Files under your finger; the keys and the line share one row there, and with the keyboard up the line saying Claude waits, and what waits for your next message, give way to them until the keyboard goes down. Where the keyboard leaves room under the screen for the line alone (66 pixels in Chrome on a Pixel 7), the keys and the line sit beside the screen instead, the keys over the line, each as tall as that room allows (30 pixels there, about as tall as the keyboard’s own keys), and the screen keeps three rows. The row above it has what a phone keyboard lacks: esc, tab, ctrl (held for the next key), the arrows, | ~ / - and paste, and scrolls sideways on a narrow phone; a key of the row sends what you have typed first, so tab completes it. While the connection comes back, what you typed stays in the line until it can go. A full-screen program such as vim or htop gets each key as you type it, and at a password prompt the line hides what you type. Swipe to scroll back, ↓ to come back to the newest output, pinch to change the text size, and press and hold for the terminal’s menu, whose Select text opens the screen as text, to select from, quote or copy. Quote there opens the quote in place, with Add a note, Send now and Add, and the view then says, above the keys, what waits for your next message. Its keys, tabs and line are a finger’s 44 pixels, beside the screen as tall as the room allows. A screen reader reads the terminal’s rows; on a phone it hears what a line printed once the shell is quiet, and Screen as text, which Tab reaches just before the screen, opens the same text on a computer. A paste goes in without control characters, so text a web page put on the clipboard cannot run without Enter.

A shell command in Claude’s reply (a bash, sh, zsh or fish code block) has Run in terminal, which asks, in place, before it runs it in a new terminal in the session’s folder, whose shell reads it from a file of its own, so its lines go in together and run as they read: a ! in it is not taken from your shell’s history, as bash and zsh take one in what is typed at their prompt. Its question shows the whole command, wrapped, its lines numbered and counted, and the blanks a line is padded with drawn (· a space, → a tab), so nothing of it sits past the block’s edge. Only Claude’s replies offer it, not a file or a tool’s output, and only for a command with nothing hidden in it: no control character, which a shell takes as a key, nothing an approval would write out, such as a character that cannot be seen or a space other than a plain one where a shell reads it as part of a word, and nothing laid out to put part of it out of sight: a run of more than 16 blanks, more than 2 blank lines in a row, a line wider than 500 columns, or more than 50 lines. Quote puts what you selected, or the screen, above the message box as a quote from the terminal, as Claude Desktop attaches one, its tab named in it, and with a note if you add one; of a long one, its first 1,500 characters, as Claude Desktop cuts any quote. Claude sees nothing of a terminal unless you put it in a message, and ! commands go into the conversation as before.

A terminal keeps running when you close the page or your phone sleeps; when you come back, the page connects again by itself and shows the screen as it was, scrollback and a program such as vim included, with the mouse, cursor and colors it set, and goes on from there. A shell that ends keeps its last screen, with Start again. One nobody has used for 12 hours, with nothing running in it, closes on its own, and every terminal ends when Pelican stops; its tab says so, with Start again. Up to 10 run at once, each on up to 8 pages; one nobody has typed into, that no page shows, makes room for a new one, and with 10 in use the Terminal tab lists those in other folders, to end one, asking first while a program runs in it. On several pages, the shell takes the size of the page you last typed in, or resized: a page that comes back, or shows the Terminal tab again, takes nothing from another, unless no other page shows the terminal. When a program prints faster than a phone on a slow link can show, it waits for the phone, so Ctrl C gets through at once; it waits for the computer’s copy of the screen too, by the time its work takes, so output that redraws the whole screen again and again goes in a little at a time, Pelican answering in between, and closing the terminal stops it at once.

A terminal runs in a folder as Claude Code does: one nobody has trusted that brings programs of its own is asked about first, and in one kept to your settings only, git runs none of the repository’s programs. The shell gets none of Pelican’s own settings, npm’s, Claude Code’s own (the mark it puts on what it runs, how it was started, and the id, messaging socket and token of a Claude Code session Pelican was started from), or what the Agent SDK sets in Pelican, so claude starts there as in any terminal, from your own profile. The demo has no terminal, and pelican --no-terminal turns it off. Its native part is there for macOS and Linux, on Intel and ARM; where it cannot load, such as on Alpine (musl) or after an install with --omit=optional, the terminal says why, and ! commands work as before.

Side chats

Ask something on the side without disturbing the session, as with Claude Desktop’s side chats: select text in the conversation and pick Start a side chat, pick it in a reply’s or a command’s ⋯, type /btw, with or without the question, press ⌘; (Ctrl ;), or pick Side chat in the session menu. Claude answers from a copy of the session so far, and can only read: Read, Grep and Glob, no MCP servers, never Bypass, nothing to approve. Nothing goes back to the session, which can keep working meanwhile; what it left running (a background agent, a command) is its own, which the side chat’s Claude knows goes on. A passage you start one with goes with your question as Claude Desktop attaches one, and shows quoted above it.

A session keeps its side chats on the computer, so your phone and your computer show the same ones, also after a reload. Each is called by its first question, such as Side chat · Why not a class on html?. ⌘;, Side chat in the session menu and /btw without a question open the latest; the ▾ by its name lists the session’s others, the latest first, and New side chat, which starts one from the session as it is now. Something to ask while the side chat is closed, a selection, a reply, a command’s output or /btw with a question, starts a new one; while it is open, it goes there, and selected text offers Send to side chat.

On a computer the side chat shares the column beside the conversation with Changes, Files and the Terminal. Alone it takes all of it; with one of those open, from 1280 pixels wide it sits under it, and the handle between them shares the height, the pane taking the larger part until you move it and each keeping room for itself, which this browser remembers (with the keyboard, the arrow keys move it and Enter puts it back). Below 1280, where there is room for one, the one you asked for last shows and the other waits behind it: a file or a turn’s changes opened from the conversation or an answer, or a pane’s button, brings the pane forward, ⌘; the side chat, and closing one shows the other again; the session list hides while either is open. On a phone it is a sheet over the conversation, which Back closes.

Side chats are Claude Code sessions titled “Side chat”, kept out of the session list unless its options show them, where each is called by its first question, and continue in the terminal and Claude Desktop like any session. Picked in the list or found with ⌘K, one opens as its session’s side chat; opened on its own (a link to it, the usage page), it stays read-only here too: its box takes questions only, and nothing in it changes files. A branch of a side chat is a side chat too, also once the side chat it came from is gone. The first question reads the whole conversation without the session’s prompt cache, so it costs about what a long prompt does; later ones use the side chat’s own cache.

Rewind and fork

Your prompt, and Claude’s reply to it, have Rewind to here and Fork from here (see where every action is); on a reply they act on its turn’s prompt. They are how a prompt is edited, as in Claude Code and Claude Desktop.

Rewind to here goes back to before that message, as Claude Code’s /rewind does, in Claude Desktop’s words. Where Claude changed files after it, it asks Rewind to this message? with Desktop’s three choices: Code and conversation, Conversation only and Code only, which files go back and how many lines change. Where nothing changed there is nothing to choose: one tap rewinds. The files go back from Claude Code’s own copies of them, as /rewind’s Restore code puts them back, whole: changes made through shell commands aren’t reverted, and commits stay in place. The conversation goes back as its Restore conversation does: the session’s Claude starts again from just before the message, and the message’s words, its quotes and its pictures and files go back in the message box, to change and send. A Rewound here line marks the cut, with Undo rewind, which brings the messages back, the files staying as they are, until you send your next message; until then the other apps the session is in still show it whole, as Claude Code writes nothing of a rewind until a message goes. Code and conversation is all or nothing: code that cannot go back leaves the conversation as it was, an earlier rewind’s cut and all. A rewind, Undo rewind and a message go one at a time: a message sent from another page while a rewind starts Claude again goes after the cut, and a second rewind meanwhile says Claude is working; a rewind leaves the session’s name as it was. A rewind waits for Claude to stop working; while another app has the session open only its code can go back, as in Desktop, and the conversation’s first message (also after a SessionStart hook’s context), and one before a compaction, can go back in code only. /rewind (also /checkpoint and /undo, as in Claude Code), or Rewind to an earlier message in ⌘K, lists the conversation’s prompts to pick one, and a turn in Changes ends with its prompt’s Rewind to here.

Fork from here on a prompt starts a new session that copies the conversation up to just before it, with the prompt’s words, its quotes and its pictures and files waiting in the new session’s box, after anything typed there already; on a reply, the copy goes up to the end of the reply, and this session stays as it is. The session menu has Fork, a full copy.

On a Claude plan its limits are at the top; with an API key or a cloud provider it shows the cost Claude Code estimates, at API prices. Each reply counts once, also when Claude Code wrote it in several rows or copied it into a side chat or a branch; /stats counts each content block of a reply, so its totals are higher. Subagents count toward their session, and days are UTC days, as in /stats. Transcripts are read once, then only what they gained. Context, the ring by Send, shows what that session used.

An agent Claude left working in the background also says so under its step in the conversation, in Claude Desktop’s words: Running in background, with its steps, its time and what it is doing, then Finished, Failed or Stopped in background. Opened, it shows what it was asked and its steps, read again every few seconds while it runs and the step is open, with Stop in a session Pelican runs; once Claude Code says it ended, what it returned, or why it failed, is there too, and the line where Claude heard of its end leads back to it. Check-ins Claude schedules, such as /loop and reminders, are listed with when they are next due, and Cancel asks Claude to cancel one. Claude keeps running for them and for background work, past the 30 minutes after which an idle Claude otherwise closes. In apps built on the Agent SDK, Pelican among them, Claude Code stops a background command after 30 minutes, or two hours if Claude gives it a longer timeout; its tools reference says how to raise that.

A workflow Claude runs, with Claude Code’s Workflow tool, shows as a card in the conversation, as Claude Code shows one: its name and what it does, Running and for how long, or Completed in 6m 1s · 4 agents · 412.3k tokens, Failed or Stopped. On a computer a phase opens as it starts work and stays open, and Verbose opens them all. Asked to run one, Pelican shows its phases, the args its script runs with and the file it runs, as Claude Code does. In a session Pelican runs, the card follows Claude Code’s own reports as they come, and Stop ends the workflow; for a session another app runs, Pelican reads the run’s folder every few seconds while the card is on screen and the workflow runs, which it does while its agents write or a Claude Code has the session open; once Claude Code has said it did not finish, only while a Claude Code has the session open and its agents went on. The script and the result are a tap away, and the line where Claude heard that the workflow ended leads back to its card.

Folders you trust

A folder can bring programs of its own: hooks, helper commands and environment variables in its Claude Code settings, MCP servers in its .mcp.json, and in its git config filters, a file-system monitor, hooks, an external diff, diff drivers and text converters, a pager, an SSH command, a password prompt, credential helpers, a signing program and aliases, besides hooks that came in its .git folder. Security

Treat access to Pelican like SSH access: it can read your sessions and run Claude Code, and so commands, as you.

  • Every browser signs in, also on this computer. Pelican listens on 127.0.0.1 and asks for the access token in the link it prints, or for your password, so other accounts and programs on the computer get nowhere. The token is random and kept readable only by you; the password is set on the computer itself and kept as a scrypt hash. A phone signs in with a QR code that works once, for two minutes, and never sees the token or your password. Failed sign-ins are limited to 10 per client and 30 in all every 10 minutes.
  • Cookies are HttpOnly and SameSite=Strict, signed with a secret that changes with the token or password. A browser in use stays signed in; 30 days without use sign it out. Signing out signs it out on the computer too: its cookie is refused from then on, also after a restart, and its terminals and live updates close at once, in every tab.
  • Only Pelican’s own page. Its requests carry a header another site cannot add, requests a browser says come from another site are refused (reads too), and changes must come from Pelican’s origin or one you allowed. The server answers only to this computer’s names, loopback, *.ts.net and the names you configure (DNS rebinding), and only Pelican’s own origin may frame it.
  • What Claude writes stays on the screen. Images in a reply load only from Pelican. Pages and visuals Claude makes show as still pictures in a sandboxed frame; when you tap Run, their scripts run in a frame of their own that cannot reach Pelican and talks to no server but the public script and font CDNs.
  • Folders run nothing of their own until you trust them. See Folders you trust. Where git runs for Changes, it runs without hooks, the file-system monitor, external diffs, diff drivers, text converters or a pager, and fetches nothing.
  • A terminal is your shell, as you. It opens under the same checks as the rest of Pelican, runs in a folder as Claude Code does there, gets none of Pelican’s settings, and lives in memory only: at most 10, ended with Pelican. Nothing runs in one without you: Run in terminal asks first, showing the whole command, only in Claude’s replies and on its own steps and your ! commands (never one you denied, nor a subagent’s or a workflow’s), and for a command with nothing hidden in it or laid out out of sight, a paste cannot run without Enter, a new token or password closes it on every browser, signing out closes it in that browser, and Claude sees a terminal only in what you quote. Its native part is Microsoft’s node-pty, file for file, which CI checks for every platform, with the few lines of its own as read for its version and nothing that runs as it installs.
  • An update installs only Pelican, from npm, when you ask. Pelican asks the registry a global install uses, never one a project’s .npmrc names, for pelican-cc’s newest version, and reads its changelog from the package, downloaded from that registry alone, within set limits, and checked against the registry’s integrity. Update takes a signed-in request from Pelican’s own page, one at a time, never in a demo, for exactly the version the registry named; npm installs it with its integrity checks and no package scripts, only where npm itself put Pelican, and Pelican never runs sudo. SECURITY.md lists each command it runs.
  • What gets installed is what was tested. The packages Pelican uses are built into it, as CI tested them; the Agent SDK, with the Claude Code it brings for your computer, and the terminal’s native part, for your computer too, are each pinned to one version.
  • --no-auth is for when something in front of Pelican authenticates. The demo signs no one in, so it stays on 127.0.0.1 unless you pass it.
  • No copies. Pelican reads Claude Code’s transcripts where Claude Code writes them, and saves a ! command’s output too long for the conversation where Claude Code saves one, in the session’s tool-results folder, readable only by you. It stores uploads, push keys and subscriptions, the sign-ins signed out until their cookies would have expired, the folders you trusted, the folders in the system’s temp folder you started sessions in, and which sessions you pinned or archived in its state folder, keeps terminals in memory only (a command Run in terminal runs is written for its shell to read, readable only by you, and removed with its terminal), and sends nothing anywhere but your browser and, for notifications, your browser’s push service.

The whole model is in SECURITY.md. Report a vulnerability privately through GitHub security advisories.

How it works

  1. The web app talks to the server over REST and a WebSocket, which carries Claude’s reply as it is written, permission requests and status changes. Each terminal has a WebSocket of its own, for its output and your keys; the server keeps a copy of its screen to show a page that comes back.
  2. To run a turn, the server starts Claude Code with the Agent SDK, resuming the session, and passes your approvals back. An idle process closes after a while; the next message resumes the session.
  3. Everything else comes from Claude Code’s own files. The transcripts in ~/.claude/projects, read incrementally and across compactions, give each session’s history, whichever app wrote it; they are followed while anyone watches. The process registry in ~/.claude/sessions tells which sessions another app is running, and whether they are working or waiting for you.

Questions

Does it work with my Claude plan?
Pelican runs Anthropic’s own Claude Code, unmodified (the copy the official Agent SDK ships, or the one PELICAN_CLAUDE_PATH names), on your computer, signed in the way you signed in to claude. It never sees, stores or forwards your credentials, puts no service in between, and serves only you: don’t open your Pelican to other people. Signed in with a plan, what you send from Pelican is Agent SDK usage, which draws from your plan’s limits, as Anthropic’s help center says; Anthropic paused a planned change to that on 15 June 2026, so their page has the latest. An API key, Bedrock, Google Cloud or Microsoft Foundry are billed as usual. Anthropic’s rules: authentication and credential use, and using the Agent SDK with your Claude plan. Checked on 5 November 2026.
Why not Remote Control?
Use Remote Control if you are on a Claude plan and want to answer, from your phone, the prompt waiting in your terminal: Pelican cannot. Pelican shows every session on the computer without turning anything on, keeps nothing on anyone’s servers, and works with any login, API keys and cloud providers included. The comparison has the details.
Can I approve a prompt waiting in my terminal?
No: that prompt belongs to the Claude running in the terminal, so answer it there, or use Remote Control. Pelican shows that the session needs you there, and your phone gets a notification if the wait lasts about 20 seconds. Once the session is idle, you can continue it here. Work you start or continue in Pelican asks you in Pelican.
Why not SSH and tmux?
That works, and needs nothing new on the computer. Pelican is for what a terminal on a phone does badly: long transcripts, diffs, approvals in one tap, notifications, charts and pages, and history across compactions.
What happens when my computer sleeps?
A computer that is asleep runs nothing: Pelican does not answer, and Claude does not work. While Claude works, Pelican keeps the computer from going to sleep on its own, though a closed laptop lid still sleeps unless the laptop is on power with a display attached. To reach Pelican at any time, keep the computer awake, as Keep it running shows.
Does it send my code anywhere, or phone home?
No. Pelican is free and MIT licensed, with no account and no telemetry. It talks to your browsers and to Claude Code on the same computer and, if you turn notifications on, to your browser’s push service, with the content encrypted. Claude Code talks to Anthropic, or your provider, as it always does.
Why is the install about 150 MB?
The official Agent SDK, which Pelican runs Claude Code through, brings its own copy of Claude Code, for your computer alone: about 150 MB to download, about 400 MB on disk. Pelican itself is about 2 MB to download and 6 MB on disk. The live demo needs no install at all.
How does Pelican keep up with Claude Code?
Each release moves to the newest Agent SDK, and the Claude Code it brings, once Pelican’s tests pass with it. Claude Code coverage says what Pelican does of Claude Code’s features, and Which Claude Code runs how to run your own.
Does it work with an API key, Bedrock or Google Cloud?
Yes: Pelican uses whatever Claude Code is set up with, Microsoft Foundry and LLM gateways included.
Can I use it while the same session runs in the terminal?
Yes. Pelican shows that the other app is working on it and follows along. Sending from Pelican then starts a second Claude in that conversation, as the message box says, so wait for the other one to finish first.
Several computers?
Run Pelican on each; each is its own page. Add them all to your Home Screen.
Windows?
Pelican runs on macOS and Linux. Native Windows does not work yet: ! commands and the status of other apps’ sessions assume a Unix system, and Pelican says so when it starts there. WSL is Linux, so Pelican should run there, next to Claude Code, untested so far; reports are welcome.
