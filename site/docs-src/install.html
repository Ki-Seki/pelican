On the computer where you use Claude Code, with Node 22.12 or newer and Claude Code installed and signed in: install it with curl -fsSL https://claude.ai/install.sh | bash, then run claude once and log in, or set an API key the way Claude Code reads it. Pelican runs on macOS and Linux, and on Windows in WSL.

npm install -g pelican-cc
pelican

Pelican prints a link, http://localhost:7860/?token=…. Open it: it signs this browser in, and your sessions are there already. pelican token prints it again, and pelican --open opens Pelican in this computer’s browser.

Pelican is small, about 3 MB to download and 9 MB on disk: it brings no Claude Code of its own, as it runs yours. The first time it starts, it fetches Anthropic’s Agent SDK from npm, which it runs Claude Code through: about 60 MB on disk, once for each version (see Which Claude Code runs). The command is also called pelican-cc, for computers where Python’s Pelican already has pelican; if npm stops with EEXIST on bin/pelican, use npx pelican-cc, or install into another prefix.

Just looking?

To look first, open the live demo, which needs nothing installed, or run npx pelican-cc --demo for the same made-up sessions on this computer: a small download, and the demo needs no Claude Code and fetches no Agent SDK. To run Pelican from a clone instead: git clone https://github.com/Ki-Seki/pelican && cd pelican && npm ci && npm run build && npm link.

Which Claude Code runs

Pelican runs your own Claude Code, the claude your terminal runs: the first on PATH, or, where Pelican’s PATH has none (a service, an app), the one Claude Code’s installers put in their own places: ~/.local/bin/claude for the native installer, Homebrew’s, /usr/bin/claude for the apt, dnf and apk packages, or npm’s. PELICAN_CLAUDE_PATH names another one. The start banner says which Claude Code runs and whether it is signed in; if it is not, pelican login signs it in with Claude Code’s own login. Where there is none, the banner, pelican login, pelican --version, Settings › About and your first message say how to install it. Settings › About shows the version too, and pelican --version prints the versions of Pelican, Claude Code, the Agent SDK and Node on one line, the line to put in a bug report.

Claude Code keeps itself up to date, and claude update updates it at once: Pelican runs the new version from the next session it starts. Each Pelican release moves to the newest Agent SDK once the tests pass with it and the Claude Code it was made with; when yours is older than that one, the start banner and Settings › About say so, with claude update to run.

The Agent SDK is Anthropic’s, and its license lets no one else ship it, so Pelican fetches Anthropic’s own package from npm the first time it starts, and says so in its terminal: exactly the version Pelican was tested with, without the optional packages that would bring a second copy of Claude Code, about 60 MB on disk in ~/.local/state/pelican/agent-sdk, once for each version, the copies of older versions removed. It runs the npm beside the Node that runs Pelican, with your npm settings (registry, proxy), never a project’s. Where npm cannot fetch it, Pelican says what npm said, and the command that fetches it by hand; it tries again when it next needs it. The demo fetches nothing.

Keep it running

Pelican only answers while it runs. This keeps it running in the background: it starts when you log in, and again if it stops.

pelican service install

On macOS it is a login item (a launchd agent), with its log in ~/Library/Logs/pelican.log. On Linux it is a systemd user service: journalctl --user -u pelican shows its log, and loginctl enable-linger keeps it running after you log out. pelican service status shows how it is doing, pelican service restart restarts it, and pelican service uninstall removes it. The service needs Pelican installed with npm install -g, not run through npx. Variables that look like secrets, such as ANTHROPIC_API_KEY, are not copied into it, nor, when you run the command inside a Claude Code session or an IDE’s terminal, what that session set for itself (its id, its sockets, the IDE’s port); your own Claude Code settings are. Its log never holds the sign-in link: pelican token prints that.

While Claude works, in Pelican or in another app, Pelican keeps the computer from going to sleep on its own (PELICAN_KEEP_AWAKE=0 turns that off). A closed laptop lid still sleeps, unless the laptop is on power with a display attached. A computer that is asleep answers nothing, so to reach Pelican while Claude is idle, keep the computer awake: on a Mac on power, with the lid open, caffeinate -s does it while it runs; on Linux, systemd-inhibit --what=sleep sleep infinity; or use your system’s power settings.

Update and remove

Settings says first thing when a newer Pelican is out, with what changed in it, and its gear in the session list has a dot meanwhile. Pelican asks npm’s registry once a day, and when Settings opens: the registry npm install -g uses, as your npm settings name it, never one a project’s .npmrc names in the folder Pelican was started from. Offline, it says nothing. Updating Pelican leaves your Claude Code as it is: claude update updates that. A new Pelican with a newer Agent SDK fetches it as it starts.

Where you installed Pelican with npm install -g, into npm’s global folder, Update does it all: npm installs that very version first into a folder of its own, where Pelican checks that it starts, then over your install, with the same prefix, checking each download against the registry’s integrity; then Pelican starts again, through launchd or systemd when it runs as a service, and in its own place, in the same terminal, when you started it there. Open pages reconnect by themselves, show the new version and say so. If anything fails, the version that ran goes on running, and Settings says what failed.

An update restarts Pelican, which ends Claude’s processes, background tasks, the checks Claude scheduled and terminals, and the messages queued for the end of a turn, which are not sent; transcripts, files, pins, settings and drafts stay. So while anything runs (a session working or waiting for you, messages queued for the end of its turn, background agents, workflows or commands, a /loop or a reminder Claude scheduled, a program in a terminal, a ! command), Settings lists it first, each check by its name, with Update now and Update when idle, which waits until nothing has run for a minute; Settings shows it waiting, with Cancel. When a session’s Claude starts again, as it does for its next message, Claude Code schedules again the checks it would still keep there: one that repeats, until a week after it was made, and a reminder, until its time; not a /loop given no interval, which Claude paces itself. While Pelican replaces your install and starts again, nothing new starts: a change, or anything that would start Claude Code, git, gh, a terminal or a search, waits for the new version.

Where Pelican cannot update itself, Settings shows the command to run instead, and why: run through npx, pnpm dlx or bunx, npx pelican-cc@, pnpm dlx pelican-cc@ or bunx pelican-cc@ with the new version, to start Pelican with once you stop it; from a clone, git pull and a build; installed by pnpm, Yarn, Bun or Volta, that tool’s command; installed into another prefix than npm’s, such as one a script of your own keeps, npm install -g --prefix with it, for you or your script to run; in a global folder root owns, sudo npm install -g. Pelican never installs over a version something else keeps, and never runs sudo. By hand, npm install -g pelican-cc@latest updates Pelican; then restart it, with pelican service restart if it runs as a service.

To remove Pelican, run pelican service uninstall if you installed the service, then npm uninstall -g pelican-cc. Its own files stay until you delete them: rm -rf ~/.config/pelican ~/.local/state/pelican removes the token, the password hash, uploads, notification keys, the folders you trusted, your pins and archive, and the Agent SDK Pelican fetched. Sessions started without a project keep their folders in ~/scratch. Your Claude Code sessions belong to Claude Code and stay where they are.
