Changes and files

The header’s Changes, Files and Terminal buttons open Changes and files at that tab (on a phone, its one button, or the tiles at the top of the session menu). Changes’ button counts the lines changed as Claude Code’s /diff does: on a branch with commits beyond where it split from the default branch (the newer of where it meets origin’s and the local one), those commits and what is not committed yet together; otherwise what is not committed. Changes shows, in Claude Desktop’s words, All changes (by that rule, “vs main”, the files not committed first), Uncommitted changes where that differs, and, under Turns, what one turn changed, cut and counted as /diff does (what Claude does in answer to a ! command is that command’s turn), read from Claude Code’s own record, so also in a folder git does not track. A turn ends with its prompt’s Rewind to here. A file’s row opens its diff, with line numbers, and has its path’s menu on a right-click or a long press.

At the foot of Changes, Commit changes and Create PR are Claude Desktop’s: a tap sends Desktop’s own request to Claude at once, word for word, so Claude Code reads the same request whichever app sent it, and a second tap while it goes sends nothing more. While Claude works, a request waits for the turn to end as a queued message, never steered into the work at hand, whatever Settings says for what you type, and goes as a message of its own, as Desktop sends each: its button then says Queued, with Take back, which takes it out of the queue as × does above the message box. Neither renames the session: one Claude Code names by its last prompt keeps the name it had, in the list, the header and notifications, as Desktop keeps a session’s title, and once its Claude has ended Pelican records that name back where Claude Code keeps it, for the terminal’s /resume and the other apps. ⌘-click (Ctrl-click), or a long press on a phone, puts it in the message box first, to read and change. Create PR’s ▾ picks Create draft PR for it, remembered as in Desktop. Create PR is offered on a branch other than the default one with changes of its own, where origin is on GitHub, or where there is no remote at all (Claude then sets one up first, asking you how). Claude commits, pushes and opens the pull request itself, with your permission rules, hooks and attribution; Pelican runs no git that changes anything, and has no Push, as Desktop has none. The request shows in the conversation as /create-pr, as in Desktop, also among prompts Claude Code took in together, and so does it in Export; the pull request Claude names in Desktop’s <pr-created> tag is a card with View PR; where the GitHub CLI (gh) is installed and signed in on the computer, the card says what GitHub says of it now, its title, open, a draft, merged or closed, its branches and its checks, read again while they run. Only a github.com pull request’s address is asked about; a card for any other names its host first, as your browser would open it. A reply shows at most five cards.

In a diff, tap a line to comment on it, or, on a phone, hold a line and drag over the lines to comment on together; with a pointer, click a line, use the + its number shows, or select lines for Add comment, and a right-click has Copy and Add comment. A comment is written in Claude Desktop’s box at the line: Cancel · Send to Claude · Add comment (Enter adds it, ⌘ Enter or Ctrl Enter sends it to Claude), on one line or a few in a row, removed lines alone being Desktop’s “before changes”. As in Desktop, comments belong to the session and wait above the message box with your quotes, going with your next message, or with them on their own with Send now or ⌘ Enter (Ctrl Enter). On a phone, where this view covers the box, its foot says what waits.

Files browses the folder and searches it, by name as you type or in the text; a row has its path’s menu, a folder’s with Open in terminal. Open a file to read it with line numbers and highlighting, Markdown and HTML previewed, and Download it; its ⋯ has its path’s menu, with Attach as context. Tap or click a line to pick it, Shift-click to pick up to another, or on a phone hold a line and drag: a bar under them has Copy, Quote and Add comment, as a right-click on them does, and ⇧⌘L (Ctrl Shift L) quotes them. Beside the conversation a quote waits above the message box at once, as Desktop’s Attach as context does; on a phone it opens in place as a sheet, with Add a note, Send now and Add.

On a phone it is a view of its own, and the back gesture steps back through it; a bar at the bottom says when Claude needs you. On screens 1024 pixels wide or more it sits beside the conversation and stays there from session to session (below 1280 the session list hides while it is open), and ⌃⇧D (Ctrl Shift D) shows Changes or hides them, ⇧⌘F (Ctrl Shift F) Files, as in Claude Desktop in a browser; ⌘\ (Ctrl \) closes it from anywhere on the page, as it closes the side chat: the one you are in, else the one you opened last. Git runs only in folders you trust; turns and files show in any folder.

Terminal

A terminal runs your login shell on the computer, in the session’s folder, as Claude Desktop’s does: with the environment Claude Code has there, so npm test and git status see the files Claude is editing, and git by hand goes there. The Terminal tab of Changes and files holds the folder’s terminals, and Ctrl ` (on a Mac too) shows it, or hides it again when you press it there; Ctrl Shift ` starts a new one, as in Claude Desktop. The first terminal starts when the tab first shows; + starts another, and Open in terminal, at the top of a folder in Files or in a folder’s menu, a path’s in a reply included, starts one in that folder. Each tab is named after the program in front of it, such as zsh, npm or vim. End hangs the one shown up, as closing a window does, asking first while a program runs in it, also a job left in the background (running or stopped), but not for what your prompt keeps running for itself, such as powerlevel10k’s gitstatusd or the worker of pure’s prompt.

On a computer you type straight into the terminal, with input methods such as Chinese pinyin, the emoji picker and dictation too. Select text there for Quote (⇧⌘L, Ctrl Shift L) or Copy (off a Mac, Ctrl C copies a selection too), hold ⌘ (Ctrl) and click to open a link, which says where it goes at the foot of the screen as you point at it (on a phone a tap asks first, saying where it goes, and opens it with Open), as a program’s link can read as any words, and use Ctrl and the wheel, or a pinch, to change the text size. A right-click opens Claude Desktop’s terminal menu: Quote and Copy what is selected, Paste, Select all and Clear terminal, which clears the screen and what scrolled off it, as clear does, on every page that shows the terminal and in the computer’s copy, so a reload shows it cleared; a program in front of the shell, such as vim or htop, draws its screen again, as after Ctrl L. On a phone a tap never raises the keyboard. You type in the line under the screen, with the phone’s own keyboard, so dictation and input methods such as Chinese pinyin work, and Enter sends the line; two spaces stay two spaces, not the period a phone’s keyboard makes of them, and while you type, the screen takes the room of the header and tabs above it. On a phone on its side the screen has that room whether you type or not, about a dozen rows, and a tap on it shows the header and tabs again, or folds them, and does nothing else: what comes back takes no tap for half a second, so neither that tap nor one made at once lands on End or Files under your finger; the keys and the line share one row there, and with the keyboard up the line saying Claude waits, and what waits for your next message, give way to them until the keyboard goes down. Where the keyboard leaves room under the screen for the line alone (66 pixels in Chrome on a Pixel 7), the keys and the line sit beside the screen instead, the keys over the line, each as tall as that room allows (30 pixels there, about as tall as the keyboard’s own keys), and the screen keeps three rows. The row above it has what a phone keyboard lacks: esc, tab, ctrl (held for the next key), the arrows, | ~ / - and paste, and scrolls sideways on a narrow phone; a key of the row sends what you have typed first, so tab completes it. While the connection comes back, what you typed stays in the line until it can go. A full-screen program such as vim or htop gets each key as you type it, and at a password prompt the line hides what you type. Swipe to scroll back, ↓ to come back to the newest output, pinch to change the text size, and press and hold for the terminal’s menu, whose Select text opens the screen as text, to select from, quote or copy. Quote there opens the quote in place, with Add a note, Send now and Add, and the view then says, above the keys, what waits for your next message. Its keys, tabs and line are a finger’s 44 pixels, beside the screen as tall as the room allows. A screen reader reads the terminal’s rows; on a phone it hears what a line printed once the shell is quiet, and Screen as text, which Tab reaches just before the screen, opens the same text on a computer. A paste goes in without control characters, so text a web page put on the clipboard cannot run without Enter.

A shell command in Claude’s reply (a bash, sh, zsh or fish code block) has Run in terminal, which asks, in place, before it runs it in a new terminal in the session’s folder, whose shell reads it from a file of its own, so its lines go in together and run as they read: a ! in it is not taken from your shell’s history, as bash and zsh take one in what is typed at their prompt. Under the line that reads the file, the new tab shows the command itself, dimmed, as a terminal shows what was typed, then what it prints (in bash, zsh, fish and the other shells of sh’s family). Your shell’s history keeps the command itself, for Up and Enter to run it again, rather than the line that read its file (bash and fish 4, and zsh set to HIST_IGNORE_SPACE, as oh-my-zsh sets it). Its question shows the whole command, wrapped, its lines numbered and counted, and the blanks a line is padded with drawn (· a space, → a tab), so nothing of it sits past the block’s edge. Only Claude’s replies offer it, not a file or a tool’s output, and only for a command with nothing hidden in it: no control character, which a shell takes as a key, nothing an approval would write out, such as a character that cannot be seen or a space other than a plain one where a shell reads it as part of a word, and nothing laid out to put part of it out of sight: a run of more than 16 blanks, more than 2 blank lines in a row, a line wider than 500 columns, or more than 50 lines. Quote puts what you selected, or the screen, above the message box as a quote from the terminal, as Claude Desktop attaches one, its tab named in it, and with a note if you add one; of a long one, its first 1,500 characters, as Claude Desktop cuts any quote. Claude sees nothing of a terminal unless you put it in a message, and ! commands go into the conversation as before.

A terminal keeps running when you close the page or your phone sleeps; when you come back, the page connects again by itself and shows the screen as it was, scrollback and a program such as vim included, with the mouse, cursor and colors it set, and goes on from there. A shell that ends keeps its last screen, with Start again. One nobody has used for 12 hours, with nothing running in it, closes on its own, and every terminal ends when Pelican stops; its tab says so, with Start again. Up to 10 run at once, each on up to 8 pages; one nobody has typed into, that no page shows, makes room for a new one, and with 10 in use the Terminal tab lists those in other folders, to end one, asking first while a program runs in it. On several pages, the shell takes the size of the page you last typed in, or resized: a page that comes back, or shows the Terminal tab again, takes nothing from another, unless no other page shows the terminal. When a program prints faster than a phone on a slow link can show, it waits for the phone, so Ctrl C gets through at once; it waits for the computer’s copy of the screen too, by the time its work takes, so output that redraws the whole screen again and again goes in a little at a time, Pelican answering in between, and closing the terminal stops it at once.

A terminal runs in a folder as Claude Code does: one nobody has trusted that brings programs of its own is asked about first, and in one kept to your settings only, git runs none of the repository’s programs, or, where git cannot be told to leave one out, no terminal starts. The shell gets none of Pelican’s own settings, npm’s, Claude Code’s own (the mark it puts on what it runs, how it was started, and the id, messaging socket and token of a Claude Code session Pelican was started from), or what the Agent SDK sets in Pelican, so claude starts there as in any terminal, from your own profile. The demo has no terminal, and pelican --no-terminal turns it off. Its native part is there for macOS and Linux, on Intel and ARM; where it cannot load, such as on Alpine (musl) or after an install with --omit=optional, the terminal says why, and ! commands work as before.

Visuals and pages

What Claude makes to be looked at is shown that way. Charts and diagrams it draws as Claude Desktop visuals appear in the conversation, a page or SVG it writes opens rendered (with its code a tap away, and full screen), and html and svg blocks in a reply can be previewed. They show as still pictures, in a sandboxed frame that cannot reach Pelican, your cookies or its API; their scripts run only when you tap Run. Visuals show only for tool calls that ran.

Files Claude sends you (Claude Code’s SendUserFile) show where it sent them, as in Claude Desktop, while it works and after a reload, under the words Claude sends with them: pictures in place, side by side at their own size when they come alone and as small squares beside other files, larger on a tap; a video or a sound in a player; a page or an SVG as such a still preview; text to read, Markdown as it reads; a PDF in your browser’s own viewer, in a tab of its own; anything else as a card to download, with its name and size. A file Claude meant you to save (its display hint, attach) stays a card until you open it, and each one can be downloaded. One that is no longer where Claude sent it says No longer on this computer, before you tap anything, and one larger than 200 MB that it is larger than Pelican serves. A character in a file’s name that hides or turns text around shows as ⟨U+…⟩, with a warning, as in an approval. In the sessions Pelican runs, Pelican tells Claude Code it shows the files Claude sends (CLAUDE_CODE_ATTACHMENTS_BY_PATH), as Claude Code expects of an app that does, so the tool is on there; nothing is uploaded, and Pelican shows each file from where Claude Code recorded it, as it is when you look. A file outside the session’s folder is asked about first, as a read there would be. Pelican shows only the files Claude Code recorded as sent in that session.
