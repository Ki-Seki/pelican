Talking to Claude

  • The first chip picks the model, then the effort level (up to max), Fast mode and Ultracode, as Claude Code’s /model does; the second picks the permission mode. Both belong to the session, which keeps them; a change reaches a Claude already at work from its next step.
  • Type / for the list of commands, @ for files, folders and subagents, or pick them from +. Commands that only work in a terminal, such as /exit or /theme, are left out. /clear, /reset and /new start a new session in the same folder with the same settings, Bypass aside.
  • Attach photos and files with + (⌘U, Ctrl U), paste them, or drop them anywhere on the conversation. Pictures the API cannot take as they are, such as HEIC or SVG, go to Claude as files to read.
  • Select text in a reply, your prompt or a step’s output for Claude Desktop’s two: Start a side chat (Send to side chat once one is open), which opens the side chat with the passage attached, and Quote. On a computer they sit above the selection a moment after you let go, and ↵ quotes; Quote opens a note box above the selection, as in Claude Desktop, where ↵ adds the quote with your note (or as it is, without one; if Settings has Enter start a new line, ↵ does that here too, and Add adds), ⌘ Enter (Ctrl Enter) sends it now, a steer while Claude works, and Esc lets it go. A note half written stays when you look at another session and come back. ⇧⌘L (Ctrl Shift L) quotes a selection without a note. On a phone the pair sits above the message box once the selection rests, clear of the system’s own menu; Quote puts the passage in the box with Add a note, and the keyboard comes up only when you tap that. Swiping a paragraph, a prompt or a command left quotes it too. Lines of a file are quoted from Files.
  • What goes with your next message waits above the box as chips, each kind told apart: a quote, in quotation marks; a quote with a note, as its note; a line comment, where it is and what you said. A chip is as wide as the box has room for, so a note reads in it. Click or tap one to read it whole, change its note, show it where it came from, or remove it. A / or ! command leaves them for the next message, and a message that does not go gives them back as they were.
  • Pelican writes them as Claude Desktop does, so Desktop and the terminal see your quotes as replies, and Pelican shows Desktop’s as quotes: a quote with a note as a <!-- reply --> block, a quote without one as an <!-- attach --> block (lines of a file with their path and lines, the terminal’s with its tab), and a line comment as In `src/app.ts` at line 12: with the code under it. As in Desktop, keys and tokens in a quote are masked, a quote is cut at 1,500 characters (the terminal’s keeps its end), an @ that would mention a file becomes ＠, Claude Code’s own tags in a line comment’s code (such as <system-reminder>) are escaped so the code cannot speak as Claude Code, and a message holds up to 99 quotes with a note.
  • Tap the microphone, where Send is when the box is empty, to dictate with your browser’s dictation.
  • Enter sends on a computer and starts a new line on a phone; Settings changes that. ⌘ Enter (Ctrl Enter) always sends, and the Enter that picks a Chinese, Japanese or Korean word never does.
  • What you type is kept for each session, attached files, quotes with their notes and line comments included, until you send it: leaving the chat, opening another session or reloading the page keeps it. Signing out forgets it. A message that does not go, the computer out of reach, comes back to the box with its files, above anything you typed since; a ! or / command comes back only into an empty box, and otherwise waits above it with Put back, as does a message that comes back while you type a command, its files waiting with it. A command never takes words or files that are not its own: where the two cannot share the box, Put back swaps them, and what was in the box waits in its place, Set aside.

Permission modes

The mode decides what Claude may do without asking. The names are Claude Code’s:

ManualAsks before edits and commands.
Accept editsEdits files, and runs mkdir, mv, rm and the like, in the session’s folder without asking.
PlanReads and plans; changes nothing until you approve the plan.
AutoRuns what it needs, with Claude Code’s safety checks in the background, on the models that have it.
Bypass permissionsRuns everything without asking. Only for a machine that holds nothing you would miss.

New sessions start in the mode Claude Code starts them in: the permissions.defaultMode of its settings (a folder’s own settings count once the folder is trusted), and where no file names one, Auto, as the terminal does, or Manual on a model without Auto. As in Claude Code, Auto and Bypass count only from your own or managed settings, never from a folder’s, whose Bypass starts in Manual. Settings › New sessions start with picks Manual, Accept edits, Plan or Auto, and saves it in your Claude Code settings, as /config does; it never saves Bypass. Where your own settings make Bypass the default, new sessions start in it, as in Claude Code, and Settings and the new session say so. A branch, an edited earlier prompt or a /clear of a session in Bypass starts in the mode a new session would.

A session in Claude Code’s Don’t ask mode keeps it and shows it; Pelican does not offer it. When the mode changes without being picked in Pelican, for example when Claude leaves Plan, a short line in the conversation says so.

While Claude works

Approvals appear above the message box with the diff or the command, in Claude Code’s own words, saying which subagent or MCP server asks. Several come one at a time, marked 1 of 3. Allow lets this one through. The button next to it says what it saves and where, as Claude Code would: Always allow npm test * in this project (kept in the repository’s .claude/settings.local.json), Allow all edits this session (the session switches to Accept edits) or Allow access to ~/data for this session; it is left out when Claude Code would allow more than was asked. Deny works like Claude Code’s No: without a note, Claude stops and waits for you; with one, Claude carries on with what you said. Characters that hide text or turn it around show as ⟨U+202E⟩, with a warning, and so does a space other than a plain one in a command, which a shell takes as part of a word: echo done⟨U+00A0⟩# … reads as a comment but runs. Pelican leaves such a space as it is only where it finds it in quotes, the body of a heredoc or a comment, of the command or of a script the command hands a new shell (bash -c, ssh, a heredoc or a pipe into sh, a script it writes with a redirection or tee and runs, a file a shell reads as it starts, and the like), as it does in a file’s name; quoted text with a $(, a ${ or a backquote in it counts as a word. A command that uses what can run text later in its own shell (eval, source, trap, an alias, read, declare, zsh’s (e) and $~x, setopt, arithmetic on a variable it sets to anything but a number, and the like, by its name in any case, as a Mac runs READ as read) is one it cannot tell, and so is one that runs a script by a path that is not plain text (bash "$t") or from a folder it writes into, a command longer than 64 KB, and one that would take more than a fixed time and memory to read. Where it cannot tell, it writes out every one. A script another program writes by itself (with sed’s w, sort -o, perl or python) is not followed, nor a string a program runs in a shell of its own, such as python’s os.system. In PowerShell, which takes such a space for a space, it shows as it is, unless the command hands a script to bash, sh, wsl or ssh.

A plan can be approved into Auto (where the model has it), Accept edits or Manual, or sent back with Keep planning. Questions show their short header and a preview of the option you pick; on a computer the card takes the keys as it comes, unless you are typing, and 1 to 9 pick an option by the number shown beside it, as in Claude Desktop, while a letter starts your own answer under Other; after a pick the next question comes into view. A question of one choice takes a pick or your own words, never both, as in Desktop. An MCP server that asks for something gets a card to answer: a short form, or a page to open to sign in.

However little room there is above the message box (a pane open beside the conversation, a phone’s keyboard up, a phone on its side), a card keeps its buttons, Allow and Deny, Answer and Skip, Approve, in view at its foot and its title at its head, with what it asks about scrolling between them, cut a little way off each at a quiet line, as in Claude Desktop; an approval shows what it asks about above Allow and Deny, a command whole or its first lines, the words above it going under the title where there is not room for both; the message box, Send, Stop and the model and mode stay in view under it. While a card waits, Claude’s task list and what runs in the background fold into one line under it, so its buttons sit near the thumb, and where the card has little room that line keeps to the foot of what can be seen, the card’s buttons just above it; a tap, or ⌃B, unfolds them.

While Claude works, Send sends a message now: Claude reads it at its next step, as when you type in the terminal. A quiet line above what you typed says so, and offers the other way beside it, Queue for later, a finger’s size on a phone; on a computer where Enter sends, ⌘ Enter (Ctrl Enter) does the same, as in Claude Desktop. Settings › While Claude works, Send makes Queues for later what Send does instead, and the line then offers Send now. Queued messages wait above the message box, where a tap takes one back to edit and × removes it, and go to Claude together when the turn ends, also after Stop. Stop shows while Claude works, beside Send once you have typed something; it, or Esc, ends the turn but leaves background agents and commands running, as Esc does in the terminal.

Notifications, turned on in Settings, say what Claude wants (the command, the file, the question) and, when a turn ends, the first line of the reply; tapping one opens the session. Where the device shows buttons on notifications (Chrome on a computer or Android, not iPhone), a command a notification shows whole has Allow, for this once, and Deny, which stops Claude as Deny does here: printable ASCII with one space between words, on one line, short enough for two lines of the narrowest notification, about 50 characters and fewer when they are wide. On Android, whose pop-up shows one line of a notification beside the buttons, the command must fit that one line, about 20 characters. A notification shows the command itself, never Claude’s description of it, and offers no buttons for what it might not show in full: a longer command, one with any other character, an edit or another tool opens the session, as questions and plans do. They come for the work you send from Pelican, and once when another app’s session has waited for you about 20 seconds. A new token or password stops them on every device, and signing out stops them on that one.

! commands

Start a message with ! to run a command in the session’s folder, like Claude Code’s bash mode: !git log --oneline -5. Its output shows as it comes, with how long it has run and Stop, which ends everything it started; once it ends, the end of the output stays in view, and Show all shows the rest. When it ends, Claude reads the output and answers, as in the terminal, unless your Claude Code settings set respondToBashCommands to false; that answer is a turn, like a prompt. Claude gets the output as Claude Code’s bash mode gives it: stdout and stderr together, up to 30,000 bytes or what bashOutputMaxChars sets; where that is unset, BASH_MAX_OUTPUT_LENGTH sets how much Claude Code reads back (1 to 150,000 bytes), of which Claude gets at most 30,000 characters inline. Past that, for a command that went well, Claude gets its start and where it was saved, up to 64 MB, in the session’s tool-results folder, which Show all reads; a command that failed is cut there, and says Failed once it is in the conversation. Exit code 1 from grep, diff, test or find is an answer, as in Claude Code, when that command is the last statement as Claude Code’s parser splits the line, which keeps a subshell or a { } group whole; a command in backquotes where a command would start counts too, such as `grep x f`. A command you stop gets no answer. Commands run in your login shell, without a terminal, for up to 30 minutes; one still running when Pelican stops gets up to 15 seconds to tidy up (Ctrl C again ends it at once). One that ends with &, such as !npm run dev &, returns at once and keeps running in the background. Pelican writes commands into the transcript as Claude Code does, so the terminal and Claude Desktop show them, and Pelican shows the ones run there.

Side chats

Ask something on the side without disturbing the session, as with Claude Desktop’s side chats: select text in the conversation and pick Start a side chat, pick it in a reply’s or a command’s ⋯, type /btw, with or without the question, press ⌘; (Ctrl ;), or pick Side chat in the session menu. Claude answers from a copy of the session so far, and can only read: Read, Grep and Glob, no MCP servers, never Bypass, nothing to approve. Nothing goes back to the session, which can keep working meanwhile; what it left running (a background agent, a command) is its own, which the side chat’s Claude knows goes on. A passage you start one with goes with your question as Claude Desktop attaches one, and shows quoted above it.

A session keeps its side chats on the computer, so your phone and your computer show the same ones, also after a reload. Each is called by its first question, such as Side chat · Why not a class on html?. ⌘;, Side chat in the session menu and /btw without a question open the latest; the ▾ by its name lists the session’s others, the latest first, and New side chat, which starts one from the session as it is now. Something to ask while the side chat is closed, a selection, a reply, a command’s output or /btw with a question, starts a new one; while it is open, it goes there, and selected text offers Send to side chat.

On a computer the side chat shares the column beside the conversation with Changes, Files and the Terminal. Alone it takes all of it; with one of those open, from 1280 pixels wide it sits under it, and the handle between them shares the height, the pane taking the larger part until you move it and each keeping room for itself, which this browser remembers (with the keyboard, the arrow keys move it and Enter puts it back). Below 1280, where there is room for one, the one you asked for last shows and the other waits behind it: a file or a turn’s changes opened from the conversation or an answer, or a pane’s button, brings the pane forward, ⌘; the side chat, and closing one shows the other again; the session list hides while either is open. On a phone it is a sheet over the conversation, which Back closes.

Side chats are Claude Code sessions titled “Side chat”, kept out of the session list unless its options show them, where each is called by its first question, and continue in the terminal and Claude Desktop like any session. Picked in the list or found with ⌘K, one opens as its session’s side chat; opened on its own (a link to it, the usage page), it stays read-only here too: its box takes questions only, and nothing in it changes files. A branch of a side chat is a side chat too, also once the side chat it came from is gone. The first question reads the whole conversation without the session’s prompt cache, so it costs about what a long prompt does; later ones use the side chat’s own cache.
