Rewind and fork

Your prompt, and Claude’s reply to it, have Rewind to here and Fork from here (see where every action is); on a reply they act on its turn’s prompt. They are how a prompt is edited, as in Claude Code and Claude Desktop.

Rewind to here goes back to before that message, as Claude Code’s /rewind does, in Claude Desktop’s words. Where Claude changed files after it, it asks Rewind to this message? with Desktop’s three choices: Code and conversation, Conversation only and Code only, which files go back and how many lines change. Where nothing changed there is nothing to choose: one tap rewinds. The files go back from Claude Code’s own copies of them, as /rewind’s Restore code puts them back, whole: changes made through shell commands aren’t reverted, and commits stay in place. The conversation goes back as its Restore conversation does: the session’s Claude starts again from just before the message, and the message’s words, its quotes and its pictures and files go back in the message box, to change and send. A Rewound here line marks the cut, with Undo rewind, which brings the messages back, the files staying as they are, until you send your next message; until then the other apps the session is in still show it whole, as Claude Code writes nothing of a rewind until a message goes. Code and conversation is all or nothing: code that cannot go back leaves the conversation as it was, an earlier rewind’s cut and all. A rewind, Undo rewind and a message go one at a time: a message sent from another page while a rewind starts Claude again goes after the cut, and a second rewind meanwhile says Claude is working, which it says until Claude stops; a rewind leaves the session’s name as it was. A rewind waits for Claude to stop working; while another app has the session open only its code can go back, as in Desktop, and the conversation’s first message (also after a SessionStart hook’s context), and one before a compaction, can go back in code only. /rewind (also /checkpoint and /undo, as in Claude Code), or Rewind to an earlier message in ⌘K, lists the conversation’s prompts to pick one, and a turn in Changes ends with its prompt’s Rewind to here.

Fork from here on a prompt starts a new session that copies the conversation up to just before it, with the prompt’s words, its quotes and its pictures and files waiting in the new session’s box, after anything typed there already; on a reply, the copy goes up to the end of the reply, and this session stays as it is. The session menu has Fork, a full copy.

MCP servers, usage and background tasks

MCP servers, in the message box’s + or with /mcp, lists the session’s MCP servers and whether they connected; while Claude runs in Pelican, each can be turned off or reconnected, and a line above the message box says when one fails. A server that needs you to sign in before it connects says where, once: claude mcp login and its name in a terminal on the computer, or claude.ai’s connectors page for claude.ai’s. Settings shows your account and plan, and Context and Usage and activity the plan’s usage limits as Claude Code reports them; a session warns, in grey, as a limit gets close.

Usage and activity, in Settings under your account, shows your Claude Code usage on this computer, from every app: tokens of each kind over 7 days, 30 days or all time, tokens per day, sessions, active days and streaks, and where they went by project, model, app and session, with a few highlights, such as how much came from the cache, when a usage limit was reached and how long Claude waited for you in Pelican. On a Claude plan its limits are at the top; with an API key or a cloud provider it shows the cost Claude Code estimates, at API prices. Each reply counts once, also when Claude Code wrote it in several rows or copied it into a side chat or a branch; /stats counts each content block of a reply, so its totals are higher. Subagents count toward their session, and days are UTC days, as in /stats. Transcripts are read once, then only what they gained. Context, the ring by Send, shows what that session used.

Commands, agents and workflows Claude runs in the background appear above the message box, each saying what it is doing, and the session says how many, as 1 in background; ⌃B (Ctrl Alt B off a Mac, where Ctrl B is the session list’s), as in Claude Desktop, or /tasks opens their list. A command has Stop, and Output shows what it printed; an agent’s or a workflow’s row leads to its card, where a workflow’s one Stop is. An agent Claude left working in the background also says so under its step in the conversation, in Claude Desktop’s words: Running in background, with its steps, its time and what it is doing, then Finished, Failed or Stopped in background. Opened, it shows what it was asked and its steps, read again every few seconds while it runs and the step is open, with Stop in a session Pelican runs; once Claude Code says it ended, what it returned, or why it failed, is there too, and the line where Claude heard of its end leads back to it. What Claude Code tells Claude when it starts such an agent is for Claude alone, and never shows. Check-ins Claude schedules, such as /loop and reminders, are listed with when they are next due, as are those Claude Code schedules again when it resumes a session, and Cancel asks Claude to cancel one. Claude keeps running for them and for background work, past the 30 minutes after which an idle Claude otherwise closes. In apps built on the Agent SDK, Pelican among them, Claude Code stops a background command after 30 minutes, or two hours if Claude gives it a longer timeout; its tools reference says how to raise that.

A workflow Claude runs, with Claude Code’s Workflow tool, shows as a card in the conversation, as Claude Code shows one: its name and what it does, Running and for how long, or Completed in 6m 1s · 4 agents · 412.3k tokens, Failed or Stopped. Open it for its phases in order, one a line, such as Review · 3 of 5 done; a phase opens into its agents, with their model, tokens and time, and an agent into what it was asked (one still waiting for a slot, the start of it Claude Code gives), what it returned and the last steps it took, the rest a tap away. On a computer a phase opens as it starts work and stays open, and Verbose opens them all. Asked to run one, Pelican shows its phases, the args its script runs with and the file it runs, as Claude Code does. In a session Pelican runs, the card follows Claude Code’s own reports as they come, and Stop ends the workflow; for a session another app runs, Pelican reads the run’s folder every few seconds while the card is on screen and the workflow runs, which it does while its agents write or a Claude Code has the session open; once Claude Code has said it did not finish, only while a Claude Code has the session open and its agents went on. The script and the result are a tap away, and the line where Claude heard that the workflow ended leads back to its card.

Hook feedback, such as why a prompt was blocked, warnings and the output of commands like /cost show in the conversation as notes.

Folders you trust

A folder can bring programs of its own: hooks, helper commands and environment variables in its Claude Code settings, MCP servers in its .mcp.json, and in its git config filters, a file-system monitor, hooks, an external diff, diff drivers and text converters, a pager, an editor, a merge driver, an SSH command, a password prompt, credential helpers, a proxy for git://, an ext:: remote and the setting that lets one run, a remote’s upload-pack and receive-pack, a command for an alternate’s refs, a recent objects hook, add -p’s diff filter, a trailer’s command, a submodule’s update command, a signing program, aliases, and the programs of git mergetool, difftool, help, send-email, imap-send, instaweb, git gui and git svn, besides hooks that came in its .git folder. Claude Code asks before it runs them in a terminal, but not in a session started through its SDK, so Pelican asks. Its settings can also pick a model, an effort, fast mode, Ultracode or a mode for its sessions, which count only once you trust it, as in Claude Code: until then a new session’s model and mode sheets say they wait, and they are asked about with its programs. The first time Claude Code would start in a folder nobody has trusted, and the folder brings any of these, Pelican lists them, read as Claude Code reads them (from the folder up to the repository’s top, and the .mcp.json of each folder above it but your home folder and those that hold it), and offers Trust and start or Use my settings only; a settings file it cannot read is listed by its name. What it warns of is always listed, and so is what the repository’s git config runs; when a folder brings more than the sheet shows, it names the first files above the list and how many more, and the folder is asked about all the same. With your settings only, Claude Code leaves out the folder’s settings, hooks, MCP servers and CLAUDE.md, and git runs none of its programs: each of the repository’s git settings that names one gets yours, or one that runs nothing of the folder’s, so there git diff stops rather than run its external diff (git diff --no-ext-diff shows the diff), and a commit’s message opens in your editor. A folder whose git config names what git cannot be told to leave out, a remote’s upload-pack or receive-pack, or a recent objects hook, does not start with your settings only. Folders trusted in Claude Code, folders Claude has already worked in and scratch folders Pelican made are not asked about.

Settings and keys

Settings holds what applies everywhere: the appearance, the default transcript view, what new sessions start with (model and mode), what Send does while Claude works, sends now or queues for later, the Enter key, suggestions of what to ask next, notifications, your account and plan with Usage and activity, the QR code for your phone, the versions that run, and a newer Pelican when one is out (see Update). What belongs to one session, such as its model, mode or view, is set in that session.

What new sessions start with is Claude Code’s own settings, which the terminal and Claude Desktop read too: your user settings (~/.claude/settings.json, or settings.json in CLAUDE_CONFIG_DIR), a folder’s .claude/settings.json and .claude/settings.local.json once you trust the folder, and managed settings, each over the one before. Pelican keeps none of its own. Settings › New sessions start with shows the model, its effort and fast mode, and the mode, and where each comes from: Claude Code’s default, your settings, managed settings or Pelican’s environment (ANTHROPIC_MODEL, CLAUDE_CODE_EFFORT_LEVEL). A change there is saved in your user settings, as Claude Code’s /model, /effort, /fast and /config save it: model, the model’s modelSettings.<model>.effortLevel, fastMode and permissions.defaultMode, every other key left as it is. Max effort and Ultracode are not offered there, as Claude Code keeps neither as a default; Ultracode is on for new sessions only where a settings file turns it on. A file that is not valid JSON is left as it is, and Settings says so. In a new session, the model and mode sheets say where the folder’s or managed settings decide instead of yours, and which of the folder’s wait until you trust it; Default picked there, where a file names another model or effort, is Claude Code’s own, as /model default and /effort auto make it. A model’s effort set under an alias of it (opus) counts for it, and maxEffortLevel caps it, as in Claude Code; a model the picker does not list, such as opus[1m], shows as itself, with its model’s efforts.

As in the terminal, a model, an effort or fast mode picked in a session’s model sheet is saved for new sessions too, as /model, /effort and /fast save it; Max effort, Ultracode and the mode stay with that session. A session already running keeps what it started with.

On a computer the keys are Claude Desktop’s, as it takes them in a browser: Esc stops Claude, ⌘K (Ctrl K) opens the command menu, ⇧⌘K (Ctrl Shift K) searches sessions, ⇧⌘O (Ctrl Shift O) starts one, ⇧⌘, (Ctrl Shift ,) opens Settings, ⌘B (Ctrl B) hides or shows the session list, ⌘/ (Ctrl /) lists the keys; ⌥⌘R (Ctrl Alt R) renames the session, ⌥⌘O (Ctrl Alt O) forks it, ⌥⌘A (Ctrl Alt A) archives it, ⌘; (Ctrl ;) opens a side chat, Ctrl O steps through the views and ⌃B (Ctrl Alt B) opens what runs in the background; ⌃⇧D (Ctrl Shift D) shows Changes, ⇧⌘F (Ctrl Shift F) Files, ⌃` (Ctrl `) the terminal and ⌃⇧` (Ctrl Shift `) opens a new one, and ⌘\ (Ctrl \) closes the pane beside the conversation, the one you are in or else the one opened last; ⌘U (Ctrl U) adds files, ⇧⌘I (Ctrl Shift I) opens the model, ⇧⌘E (Ctrl Shift E) its effort, ⌥⌘F (Ctrl Alt F) turns fast mode on or off and ⌥⌘M (Ctrl Alt M) opens the mode. With text selected, ↵ quotes it while Quote shows above it and ⇧⌘L (Ctrl Shift L) quotes it without a note; in the note box, ↵ adds and ⌘ Enter (Ctrl Enter) sends now; while Claude works, ⌘ Enter (Ctrl Enter) is the other way to send, Queue for later or Send now; when Claude asks a question, 1 to 9 pick an answer, the number shown beside each. A browser’s own keys are left to it, and ⌘, and ⌘⇧D work as well where a browser passes them on. With a screen reader, each turn has a heading, and Pelican says when Claude asks for approval, asks a question, presents a plan or replies, and when the connection drops or comes back. With Reduce motion on, status dots hold still and jumps are instant.
