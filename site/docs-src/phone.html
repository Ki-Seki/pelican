Only you get in

Pelican listens on 127.0.0.1, so only your computer can reach it until you choose a way in, and every browser signs in. Whoever can use Pelican can run Claude Code as you, so pick a way in that keeps everyone else out.

Tailscale (recommended)

Your phone and computer join the same private network, and tailscale serve puts Pelican behind HTTPS, which notifications need.

No Tailscale yet? Install it on the computer and on the phone, signed in to the same account on both. pelican phone says how for your system too.

Mac

The Tailscale app, from the App Store or tailscale.com/download/mac.

Linux

curl -fsSL https://tailscale.com/install.sh | sh, then sudo tailscale up, and open the link it prints to sign in. On Linux tailscale serve is root’s until you make yourself Tailscale’s operator: sudo tailscale set --operator=$USER.

WSL on Windows

As on Linux, inside WSL, where Pelican runs. Tailscale's service starts through systemd, which WSL leaves off unless /etc/wsl.conf turns it on. This prints systemd where it is on:

ps -p 1 -o comm=

Where it prints something else, turn it on (where /etc/wsl.conf has a [boot] section already, put systemd=true under it instead), then run wsl --shutdown in PowerShell and open Ubuntu again:

printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf

Then install Tailscale as on Linux. To Tailscale, WSL is a device of its own, and Windows is another: in Windows' own browser, open Pelican at http://localhost:7860, as the ts.net address opens only on devices on your tailnet. WSL can stop once its last window closes, and Pelican with it: keep a WSL window open while you use Pelican from the phone.

With Tailscale already on Windows, Tailscale advises using that one alone: run tailscale serve --bg 7860 in PowerShell, which reaches Pelican in WSL through localhost, then pelican phone https://<this PC>.<your tailnet>.ts.net in WSL. Should WSL not reach that address, open it on the phone and sign in with a password (pelican password).

On the phone: the Tailscale app, from the App Store or Google Play, signed in with the same account. A phone runs one VPN at a time, so turn any other VPN or proxy app off.

First time

The first time, tailscale serve asks you to turn on HTTPS for your tailnet, with the link that does it. Then:

tailscale serve --bg 7860
pelican phone

pelican phone finds the address tailscale serve gave Pelican, checks that it reaches this very Pelican, and prints a QR code. Scan it with the phone’s camera: Pelican opens there, signed in. The code works once, for two minutes; press Enter for a new one. On a Mac with only the Tailscale app, tailscale is not a command in your terminal; run pelican phone, and it prints the command with the app’s own path.

Once Pelican knows the phone’s address, its start banner shows the QR code, and so does Settings › On your phone on the computer. To give the address yourself, run pelican phone https://laptop.example.ts.net, or start Pelican with PELICAN_PUBLIC_URL set to it. Or set a password with pelican password and type it on the phone.

When the phone cannot open it

An address on your tailnet, …ts.net, opens only on the devices on it. tailscale status on the computer lists them, and the phone must be one, signed in with the same account. Where only the computer is on it, pelican phone says so under its QR code.

  • ERR_CONNECTION_CLOSED, the site “closed the connection”: the request never reached Tailscale, as a proxy (Clash and the like) on the phone or the computer took it. On the computer, add ts.net and 100.64.0.0/10 to the proxy's direct rules, or turn it off. On a phone, which runs one VPN at a time, turn the proxy's VPN off while you use Pelican: with it on, Tailscale is off.
  • The site cannot be reached, or its name is not found: this device is not on your tailnet, or Tailscale on it is off. Open the Tailscale app, sign in with the same account, and connect.
  • In WSL: Windows is a device of its own to Tailscale. Its browser opens Pelican at http://localhost:7860; tailscale status in WSL lists WSL alone until another device joins.

An SSH tunnel

From a laptop, or a phone app that forwards ports (Termius, Blink): ssh -N -L 7860:127.0.0.1:7860 you@computer, then open the link Pelican printed.

Your own reverse proxy

Put Pelican behind Caddy or nginx with HTTPS, and tell it the public address:

PELICAN_PUBLIC_URL=https://pelican.example.com pelican

Pelican then answers to that name and takes changes from it, and pelican phone makes its QR codes for it. If the proxy already authenticates, add --no-auth to turn Pelican’s own sign-in off. With the proxy on the same computer, PELICAN_TRUSTED_PROXY=1 lets Pelican count failed sign-ins per client. Pelican works under any path prefix, so https://example.com/pelican/ is fine.

On the home network

pelican --host 0.0.0.0 prints a QR code for your phone and works across your Wi-Fi, but over plain HTTP: the sign-in travels in the clear and notifications are off. Prefer Tailscale.

Add it to your Home Screen

In Safari, Share → Add to Home Screen; in Chrome, Install app. Pelican then opens full screen, and on an iPhone notifications only work this way.
